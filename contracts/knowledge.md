# 约束权限感知知识管道

对齐 R02/R10/R12、A05/A06/A08、V06—V08；依据 [知识架构](../enterprise-agentic-os-architecture/05-权限知识与计算隔离.md)。本文件为 M3 实现契约，当前尚未实现；不作为知识能力已可用的说明。

## 分离内容与权限

1. 绑定来源：管理员配置租户、安装、来源及同步身份；普通用户与模型不能注册来源或自授权限。
2. 接收内容：输入来源文档 ID、源版本、正文摘要、切片和引用锚点；同内容版本原子发布，未完成或缺少可信 ACL 时不可见。
3. 接收权限：独立保存源授权版本、有效期、同步健康状态与有效主体；保留允许、拒绝及切片限制。拒绝优先，切片不得扩展文档权限。
4. 处理乱序：内容与权限有各自单调版本；重复事件同内容幂等，旧版本拒绝，冲突显式失败。权限变化不触发内容重建。
5. 阻断撤回：删除或失去来源授权先使内容不可见；物理清理独立执行。游标失效、超期或来源权限不可确认时拒绝检索，不延长缓存授权。

## 限定读取边界

- 复用身份：解析当前 ExternalIdentity 为有效租户/成员；固定来源安装，不使用请求携带的部门或角色作为授权依据。
- 过滤出库：候选、标题、正文、锚点与计数在数据库查询内授权；未经许可内容不能到达重排、模型或日志。
- 校验引用：引用绑定来源、文档内容版本、切片与锚点；点击、预览和交付重验当前身份与权限，禁止把已缓存文本当作权限证明。
- 隔离上下文：授权版本和内容版本纳入结果标识；权限变化后既有结果不得继续用于交付。群聊接收范围未确认时不输出正文。
- 显式能力：未经认证的源权限语义、检索驱动或锚点类型明确拒绝；不把部门/角色简单并集转换为全员允许。

## 实施首切片

先建立 PG 知识模块、内容/ACL 独立版本与发布状态、当前主体的授权读取和引用核验，复用现有事务与身份契约。使用合成来源及明确成员 ACL 验证底线；原生组织继承、来源连接器、Embedding 与混合召回按后续切片接入，未接入能力保持禁用。

验收顺序：内容先到不可见 → ACL 到达可读 → ACL 撤销立即不可读且内容版本不变 → 旧事件不能复活权限 → 删除先不可见 → 跨租户/安装/成员与失效身份无法读取正文、标题或计数 → 事务失败不半发布。全部使用真实 PG；SQL 授权通过不代表向量召回质量达标。

首切片完成后再接来源同步与检索消费者；完整 M3 仍须落实原生权限语义、双通道恢复、引用交付、计算隔离及轻量部署验收。
