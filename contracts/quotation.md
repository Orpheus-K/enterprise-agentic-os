# 核算版本化报价初稿

对齐 R03/R04/R06/R09、T01—T04、A04、V03/V06。产品口径来自 [报价场景](../enterprise-agentic-os-docs/02-用户场景与业务闭环.md)。当前完成确定性计算、版本持久化与受控改单重审；Worker 已接入受控工具数据与本地核价；真实企业目录认证和正式文件交付仍待完成。

## 固定输入来源

- 传入获授权目录：Catalogue 包含价格目录 Revision、币种、计价口径及 SKU 标准单价；标准价不得由模型自行提供。授权连接器负责证明目录来源，摘要格式检查不等于真实性认证。
- 传入业务请求：客户引用、输入证据引用、SKU、整数数量与拟报单价。输入引用不携带客户正文；引用本身不是读取权限。
- 明确规则：Policy 固定 Revision、币种、口径和特批阈值。贯穿样例显式配置 CNY、net_no_fees、8000 基点；不把示例设为所有企业的默认规则。

## 执行精确计算

1. 校验范围：本实现只支持人民币分、整数数量、同币种不含税费口径；单据 1—100 行，每 SKU 一行，数量 1—1,000,000，证据 1—32 个。单价必须大于零且不高于目录价；不支持赠品、负数或超标准价流程。
2. 拒绝缺项：目录价缺失、零分母、重复 SKU、未知币种、不同税费口径和越界金额直接失败。总金额上限为 9,000,000,000,000,000 分，保证 JSON 整数可精确表示；乘加前检查上限。
3. 核算金额：单价分 × 整数数量后求和，无浮点运算、无隐含舍入。上游目录如含阶梯定价，须先由获准业务服务提供适用价格；当前模块不计算税费、运费、汇率或毛利，也不接受小数数量。
4. 判断特批：按成交总额/标准总额的精确加权比例，与配置阈值交叉相乘比较；使用大整数避免比较溢出。严格低于才触发；不对百分比先取整，恰好八折不因本条触发。

## 创建与修改版本

- 创建初稿：New 返回 Version=1，固定报价 ID、客户、证据、目录/策略 Revision、计算算法版本、逐行金额、总金额及特批标志。
- 固定摘要：按 SKU/证据排序，SHA-256 覆盖完整对象（排除 Hash 自身）。摘要用于匹配内容，不是签名或权限证明；持久化层仍须限制写入。
- 修改价格：Revise 要求匹配旧摘要，核验旧对象可复算后接受 SKU/新单价变更；保留旧对象，创建 Version+1、PreviousHash 与新计算结果。不允许未知 SKU、重复变更或空操作。
- 限定编辑：当前只支持单价修改；改变客户、数量、证据、目录或政策须另建初稿，不能偷偷沿用旧版本。后续业务入口必须使旧审批失效、为新版本重新检查审批条件。
- 区分状态：Draft 不包含批准、正式发布或用章状态；RequiresApproval=false 只表示未命中这一折扣规则，不代表可以对外发送。

## 保存初稿并受控改单

- 保存初稿：内部 SaveQuotation 只接收可信业务适配器计算的 Version=1，对象 ID 必须为任务 ID；持有 model_running 或 tool_running 有效租约。schema 12 将只追加报价版本、任务响应检查点和审计同事务提交；未配置审批人时不得保存需特批报价。
- 区分折扣规则：初稿 RequiresApproval=true 保留安装指定审批人并沿用原挂起流程；false 跳过该报价折扣审批。此入口只实现当前报价规则，企业其他审批策略尚未组合接入。
- 查看内容：复用 GET /api/ops/approval；响应正文包含当前结构化报价。原报价内容、版本和摘要同时受审批内容摘要绑定，禁止写入普通日志。
- 修改单价：POST /api/ops/quotation，仅接受现有 Bearer 认证及指定审批人的 task.approve 授权；请求包含原 ApprovalDecision 的绑定字段，decision=amend，另带 quote_hash 和 changes=[{sku,unit_minor}]。上限 16 KiB，拒绝未知字段、尾随 JSON 和查询参数。
- 重新挂起：仅未过期 waiting_approval 可改；取得任务锁后重验当前审批身份与能力，校验原审批 ID、步骤版本、Revision、内容摘要和报价摘要。重新核价生成新报价版本，替换审批 ID/期限并递增步骤版本；全部与旧审批存档、改单记录、审计同事务。
- 重新确认：修改后即使达到八折，也保持 waiting_approval，需主管明确批准新版本。旧卡片不能批准新内容；已批准、拒绝、过期或发送中的任务不可通过本入口改价。
- 去重请求：相同请求 UUID、身份与完整内容返回原新审批元数据；不同内容复用 UUID 返回 409。重复请求仍检查当前身份和权限。请求不触发模型、外部工具或发送。
- 隔离记录：quote_versions 与 quote_edits 强制租户 RLS；运行账户只有 SELECT/INSERT，无 UPDATE/DELETE。业务方法额外绑定应用、模型 Revision 和指定审批人。旧审批正文为受保护业务记录，不是可公开诊断日志。

[真实 PostgreSQL 测试](../services/core/internal/feishu/quotation_integration_test.go) 覆盖并发改单去重、旧卡片拒绝、重启后新版本交付、跨安装/Revision、撤权、过期、审计回滚、旧租约和 HTTP 边界。交付测试使用本机 Sender 替身；完整 Worker 合成链路见下节；此组存储测试不单独证明贯穿样例。

## 接入 Worker 核价链路

1. 声明技能：manifest 的 quotation_tool 指定 tools 中的一个工具名称，工具版本仍绑定该依赖 Ref。缺少依赖拒绝导入。该声明进入技能摘要校验，改变声明须生成新技能 Revision 并重新授权。
2. 受控取数：工具返回 request、catalogue、policy。Catalogue 使用 revision/currency/basis/prices；字段必须明确，ToolInput 拒绝未知字段、尾随数据和不支持的金额类型。目录、证据及政策由获准业务服务提供；生产接入必须在服务端实施客户/产品/来源权限，不能相信模型自报的标准价或政策。
3. 固定计算：Worker 只能将声明的工具结果交给 FromTool，本地 New 精确计算。报价技能的最终纯文本输出直接失败，不允许模型绕过工具伪造报价或批准。
4. 持久恢复：工具结果先保存，核价结果以同一任务 ID 保存为报价版本。报价保存失败时保留 tool_running；租约过期后读取原成功工具结果重新计算并保存，不重发工具请求。
5. 推进审批：保存后立即进入既有挂起/交付流程。七五折等待审批，改单生成新版本并重审；恰好八折跳过这条折扣审批，只回传初稿。

[合成贯穿测试](../services/core/internal/feishu/quote_chain_integration_test.go) 从验签消息入队开始，使用真实 PG、官方 MCP SDK HTTP 服务和本机 chat-completions 替身，验证一次模型选择、一次工具取数、核价、旧卡片拒绝、改单批准和一次新版本交付。额外覆盖八折边界、工具撤权、模型绕过与保存失败恢复。已提供可读内部文本初稿及 [审批卡片贯穿验证](../services/core/internal/feishu/approval_card_integration_test.go)；正式 PDF、用章和真实外部系统认证未完成。SDK 本机替身不证明真实飞书送达。

## 交付可读初稿

- 保留原件：任务 response 与审批内容摘要继续绑定结构化 Draft；报价版本不因展示格式而变化。Claim 同时读取 quote_version，渲染前验证任务 ID、版本、摘要与可复算结果。
- 确定展示：Worker 在提交发送意图前生成纯文本初稿，列出版本、客户、产品/数量、分精度单价和合计、证据引用及版本摘要；不用模型改写金额。文本明确“非正式对外文件、未用章”，不将折扣标志当审批状态。
- 受控下载：GET /api/ops/quotation?task_id=<UUID> 返回当前版本 UTF-8 .txt 附件；沿用指定审批人、task.approve 和读取审计。撤权或审计失败不返回正文；无匿名 URL、Cookie 或查询令牌。响应 no-store、nosniff，文件名仅含任务 UUID 和版本。
- 限定接收：现有 Worker 仅回复已验证的原单聊；本功能不扩大为群聊/客户外发。下载是当前初稿视图，不是公开文档共享服务。
- 保留范围：文本初稿已可读，尚无正式 PDF、签章、审批通知或渠道卡片；这些能力不通过文案暗示已实现。

证据：[文本精度与篡改测试](../services/core/internal/quotation/render_test.go)、[下载权限与读取审计测试](../services/core/internal/feishu/quotation_integration_test.go)；贯穿测试核对修改后的可读总额和版本。

## 可选 WASM 折扣复核

安装显式配置 `quotation_wasm_sha256` 才启用[沙箱规则](sandbox.md#固定折扣规则模块wasm)。标准价、金额总和及草稿完整性仍走本契约；新稿保存和改单均须额外通过固定 WASM 规则，任何失败阻断持久化，不静默改用宿主结果。模块摘要绑定任务执行版本，旧审批、恢复和改单不能换用另一配置。未启用时保持既有整数核算。

## 正式 PDF 库层（R03/R04/R06/R12/R15、T11）

`quotation.PDFRenderer` 复用 Verify 与整数分金额，不用模型改写报价。嵌入可信配置提供的 TTF，字体 SHA-256 与版式版本共同形成 RendererHash；字体缺字明确失败。固定显示报价版本、ID、内容/目录/规则/版式摘要与“未用章”；不以生成文件代替外发许可。合成测试字体只用于测试，不能当作完整中文运行字体。

PG schema 26 的 `channel.quote_documents` 以租户/任务/报价版本唯一绑定内容摘要和 RendererHash；`reserved` 在渲染前持久提交，`ready` 仅在对象存储回读与原字节一致后提交。长计算和对象访问不持有数据库事务。仅获得新预留的调用能渲染；重启或并发重试遇到 reserved 返回待核对错误，绝不盲重生成。ready 只读回原对象并验证摘要，不能改版式或覆盖字节。内容变更必须新报价版本；未知尝试需管理员保存现场证据并核对，不提供“清空记录再试”的自动路径。

`GenerateQuotePDF` 注入受信任 Renderer 与不可变对象适配器（按租户/尝试隔离、读前限额）；当前仅合成对象适配器测试，无 HTTP/渠道下载、生产对象存储或真实外发接线。PDF 不写入任务 response，也不直接存入数据库正文。

调用者须有独立 `quotation.publish`；`task.approve` 不授予生成/读取正式文件权。锁住任务后重新核对当前身份、应用、执行版本、报价版本与摘要。需要审批或存在改单审批时必须匹配批准的 response，批准尚未过期，原审批人的身份映射与 task.approve 仍有效。对象 I/O 后再次核对授权。预留、完成和成功返回前的读取留痕使用独立 `quote_document_events`，审计失败不返回文件；生成不改变任务步骤版本。

## 用章授权模型（R06/R12/R15、A06/A08、T11）

审批、正式文件发布、用章、对外发送是独立动作。用章策略必须固定租户、报价 ID/版本/内容摘要、原 PDF 摘要、印章标识、策略版本、获权操作者、有效期与授权证据；只能处理已固定的 ready 文件。任何字段变化均使授权不匹配；撤权或无法确认当前权限时拒绝。

`SealPolicy` 固定租户、应用、印章、获权成员、金额上限和有效期，其规范摘要形成策略 Revision。`BindSeal` 再绑定报价 ID/版本/内容摘要、原 PDF 摘要和授权证据摘要；摘要仅绑定内容，不能替代可信授权来源。PG schema 27 的 `seal_policies` 仅由管理员配置，运行账户只读，恢复授权事实摘要包含该表，旧备份不能绕过当前撤权。

`SealQuotePDF` 要求独立 `quotation.seal` 和正式文件的 `quotation.publish`，复用当前审批与版本核验。`quote_seals` 以租户/任务/报价版本/印章唯一预留，签章前提交意图，产物回读一致后才转 ready；`quote_seal_events` 原子追加预留、完成和读取审计。策略、身份、原文件在签章前及 I/O 后重新检查；审计失败不返回文件。未知结果保留 reserved，后续调用明确要求人工核对，不重新调用签章器。ready 仅返回原对象。撤权不删除历史证据或伪称收回已发文件。

仅注入 `QuoteSealSigner` 和不可变对象接口；[合成 PG 测试](../services/core/internal/feishu/quote_seal_integration_test.go) 使用 PDF 注释作为替身，覆盖单次调用、重建对象后读取、独立授权、摘要错配、撤权、未知结果及审计回滚。本次不接真实印章、密钥或第三方电子签章服务，也不声明法律签名有效性；签章服务的真实授权证据、密钥托管和外发接线仍需独立设计与验收。
