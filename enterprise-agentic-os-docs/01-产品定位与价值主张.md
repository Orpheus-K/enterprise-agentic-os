# 01 产品定位与价值主张

## 一、总述：交付受控的业务结果

产品定位为企业级数字员工运行底座：帮助企业把业务 SOP、知识和系统工具转化为具有明确职责、授权与人工兜底的数字员工。核心承诺方向是“可安全授权、可持续执行、可运营维护”，具体承诺须经过验收后形成。

产品不是以拖拽画布为中心的流程工具，也不以新建一个独立聊天入口作为主要价值。管理工作台服务配置、审批追踪、审计和运营；业务交互优先融入员工已有办公入口。可视化流程可用于解释与诊断，但不作为业务逻辑的唯一来源。

## 二、客户与角色：区分采购者、使用者和责任人

| 对象 | 主要需求 | 成功证据 |
|---|---|---|
| 中小企业、部门级试点负责人 | 少量准备即可验证价值，部署和运维可承担 | 一个真实场景完成闭环，前置配置与人工投入透明 |
| 中大型企业 CIO / IT 负责人 | 接入既有身份与系统，支持私有化、升级和统一管理 | 权限不被旁路，运行可追踪，试点可延续到生产 |
| 金融、政务及集团安全合规负责人 | 授权、隔离、审批、归档与责任归属明确 | 可复核的访问和操作证据，不将产品能力等同于合规认证 |
| 制造与供应链业务负责人 | 串联订单、库存、报价等多系统工作 | 数据口径一致，异常可接管，重复执行不造成重复业务 |
| 出海企业业务负责人 | 多语种询盘、跨系统跟单和外部通信 | 草稿有依据、对外发送可控、数据使用符合企业规则 |
| 一线员工 | 在已有办公入口完成任务，知道进度与下一步 | 可获取有依据的成果，可补充信息、取消或转人工 |
| 主管 / 审批人 | 看清变更、风险和责任，移动端可决策 | 审批与具体内容绑定，修改后规则重新验证 |
| 技能维护者 / 运营者 | 业务逻辑可版本化、测试、回滚、定位问题 | 变更可比较，失败可定位，效果可量化 |

首期以销售报价为验证场景，不把全部行业特殊规则同时纳入首期。行业合规、用章和数据跨境要求由目标客户补充确认后形成交付条件。

## 三、痛点到价值：建立可验证的差异化

| 痛点 | 产品能力方向 | 价值证明方式 |
|---|---|---|
| 知识与工具权限不随用户身份生效 | 权限感知检索、工具授权、交付范围校验 | 授权用户可访问；未授权、撤权和跨租户测试均无泄露 |
| 长任务遇到故障、超时或审批等待后失去上下文 | 持久化状态、审批等待、恢复与业务补偿 | 中断后恢复正确版本；无法判定结果时停止重试并核对 |
| 复杂画布难审查、回归和定位 | 声明式技能、版本差异、发布门禁、执行轨迹 | 业务改动可审查，历史样本可回归，故障可定位到步骤 |
| 工具规模扩大后上下文成本与选择错误增加 | 工具注册治理、技能按需加载、授权内路由 | 在相同样本下比较质量、调用准确率与上下文成本 |

上述是对目标使用场景的差异化假设，不构成对 Dify、n8n 所有版本能力的断言。售前比较须记录竞品版本、部署模式、扩展能力和实际测试条件。

声明式 SOP 定义业务约束与可选步骤；动态规划负责约束内的任务探索。价格红线、授权、审批和正式交付不能交由模型自由决定。自愈限定为受控重试、替代读取、请求补充或人工接管，不允许自动扩大权限或改写规则。

## 四、产品边界与购买理由

### 4.1 产品负责什么

平台负责连接入口、身份、知识、工具、人工审批与任务状态；提供可复用技能、治理能力和效果证据。企业原有 IAM、CRM、ERP、合同系统及指标平台继续作为各自领域的权威来源。

平台不承诺取代 ERP 或 IAM，不默认拥有所有数据，不自主授予审批权，不保证任何任务都可全自动完成。生成、审批通过、签章和对外发送是不同业务动作，须分别授权。

### 4.2 商业化价值主张

1. **示范生成技能：** 将专家经验转为可审核的技能候选包，降低 SOP 建设成本。
2. **数字员工绩效与审计：** 同时向业务展示成果，向 IT 与安全展示执行证据。
3. **上线前评测回放：** 在业务受到影响前发现模型、提示词或工具变更带来的回归。
4. **垂类套件：** 通过有真实业务规则、连接器和验收样本的样板间，降低客户从空平台起步的成本。

采购理由应由试点证据支撑：授权风险减少、处理周期缩短、可交付任务增加、维护成本可控。收费结构可以评估平台授权、部署服务、业务套件和运营支持；价格、计费单位与合同范围不在本版定案。

### 4.3 价值指标

| 价值方向 | 指标及约束 |
|---|---|
| 业务产出 | 有效完成量、完成率、交付时长；区分测试、重复、取消和失败任务 |
| 人工投入 | 介入率、修改率、审批耗时；正常合规审批不等同于模型失败 |
| 质量与风险 | 违规规则命中、误报、越权阻断、证据覆盖与事实错误；阻断数不直接等于损失避免金额 |
| 资源效率 | 单个有效任务的模型、运行、存储及运维成本，不只统计 Token |
| 节省工时 | 同口径人工基线减去实际人工复核与修正时间；注明样本和估算方法，不直接等同于裁减岗位 |

## 五、收束：用业务闭环验证定位

定位成立的前提是数字员工既能完成业务，又能解释授权、等待、失败与交付。下一篇 [用户场景与业务闭环](02-用户场景与业务闭环.md) 把这些价值目标落实为可观察的步骤、状态与异常处理，作为功能需求的输入。
