# 02 存储策略与驱动契约

## 一、总述：统一的是行为契约，不是 SQL 语法

默认生产路线为 PostgreSQL 承载事务数据、权限、执行事件和队列，配合 pgvector 与经验证的全文搜索扩展。轻量路线使用 SQLite 与本地文件。驱动须满足同一行为测试，不能仅因都支持 SQL 就宣布可互换。

本篇采用五组 SPI 组织边界；其中持久化与检索分成独立子契约，因为事务状态和可重建索引的一致性要求不同。

## 二、PostgreSQL 默认生产路线

| 能力 | 设计 | 必须验证的边界 |
|---|---|---|
| 事务与权限 | 关系表与 JSONB 元数据；应用授权叠加 RLS | 连接池身份上下文隔离、角色权限、跨租户负例 |
| 向量检索 | pgvector，结合授权过滤与来源版本 | 过滤后的召回、延迟与真实查询计划；不只验证结果条数 |
| 全文检索 | pg_search/BM25 作为目标扩展，原生全文作为有说明的替代路径 | 中文/多语种分词、版本支持、许可、备份与升级；替代方案不冒称等效 BM25 |
| 事务队列 | 数据库任务记录、可见时间、租约、尝试次数与结果 | 多消费者领取、崩溃回收、超时、迟到结果与公平性 |
| 文件 | 原件与大产物放文件驱动，数据库记录引用、摘要与版本 | 文件与数据库联合备份，不形成孤儿引用或错误覆盖 |

RLS 是纵深防御，不是“数据库底层绝对杜绝越权”。运行账户不得为超级用户或具有 BYPASSRLS；表所有者与迁移身份分离，必要时 FORCE ROW LEVEL SECURITY，并检查视图、函数与运维入口。[PostgreSQL RLS 文档](https://www.postgresql.org/docs/17/ddl-rowsecurity.html)说明了绕过策略的角色情形。

`FOR UPDATE SKIP LOCKED` 只用于短事务领取任务，认领后提交再执行网络调用。它适用于队列竞争，不提供业务顺序、持久化重试或 exactly-once；这些由运行时补齐。[PostgreSQL SELECT 文档](https://www.postgresql.org/docs/current/sql-select.html)明确其跳过锁定行的行为。

## 三、五组 SPI：默认后端与候选后端

| SPI 组 | 统一契约 | 轻量路线 | 生产默认/可选 | 集团候选 |
|---|---|---|---|---|
| 1 持久化与检索 | 原子提交、条件更新、事件序号；授权检索、索引版本与删除 | SQLite；LanceDB 为向量候选，按构建及过滤能力认证 | PostgreSQL＋pgvector；pg_search 经认证启用 | 达梦、OceanBase、高斯DB 与对应检索驱动，分别认证 |
| 2 事件与长任务 | 持久化入队、认领租约、延迟、确认、重试、死信、取消 | SQLite 任务表为事实源；Channel 仅加速唤醒 | PostgreSQL 事务队列；Redis Streams 非默认候选 | 客户企业消息总线，配合数据库 outbox/inbox |
| 3 文件与原件 | 写入、读取、摘要校验、权限、生命周期与备份 | Local FS，单机专用目录 | 企业 NAS 或兼容对象存储；MinIO 为可选制品 | OSS、OBS、私有 Ceph，按接口与权限能力认证 |
| 4 缓存与锁 | 可失效缓存；租约与 fencing 条件提交 | 进程内缓存，Ristretto 为候选；数据库保证执行互斥 | 进程内缓存默认；Redis Sentinel/Cluster 按需要启用 | Tair 等客户认可组件，认证后启用 |
| 5 代码沙箱 | 能力声明、隔离执行、资源限制、取消、产物回收 | wazero/WASM 处理兼容工作负载 | 独立隔离容器池，gVisor 为候选 | Firecracker 微虚拟机为候选，依赖宿主能力 |

原提案“Channel＋自建 WAL”收敛为 SQLite 持久化任务与日志机制：Channel 丢失不能导致任务丢失，避免再维护一套自制恢复日志。若引入专用 WAL，须额外证明事务对齐与恢复正确性，不属于当前默认。

生产默认无需 Redis、Kafka、RabbitMQ、Elasticsearch 或 ZooKeeper。中间件并非禁止使用，只有经容量或客户约束证明必要，并完成运维与一致性验收后才扩展。对象存储属于文件层，不宣称整个产品只存在一个有状态组件。

## 四、可替换必须保持的不变量

1. 任务状态、执行事件和 outbox 在单一事务边界内提交；跨存储发送依靠可靠投递和接收去重，不能假设跨驱动分布式事务。
2. 任务至少一次执行尝试；外部效果通过幂等键、结果核对、版本约束和人工收口保证。数据库原子性不覆盖外部系统。
3. 缓存不得作为权限或任务状态唯一事实源。撤权以授权版本及失效机制约束；缓存不可确认时回源或拒绝，不延长旧权限。
4. 锁过期后旧执行者可能仍在运行，提交结果必须检查租约世代。外部工具还须通过自身幂等/版本检查或人工核对，不能只依赖分布式锁。
5. SQLite 不提供与 PostgreSQL 相同的 RLS 能力，轻量版须通过应用策略与强制授权查询保证同样业务底线，并运行跨租户/跨用户负例。
6. 达梦、OceanBase、高斯DB 不假定兼容 PG 扩展或锁语义。驱动报告支持能力，不支持的配置启动即报错；首批只认证明确组合。

对象写入先形成临时对象，数据库记录有效引用后再确认可见；失败对象可清理。清理需保护活跃上传、审批文件和审计保留对象。索引属于可重建派生数据，重建不放松访问权限，恢复时可暂时降低可用性而不返回未经授权内容。

## 五、收束：存储能力服务于可恢复执行

统一驱动让部署改变时业务规则不变，但每种后端仍需数据迁移、索引重建与验证，不能仅改配置原地变成集群。下一篇 [持久化执行与审批恢复](03-持久化执行与审批恢复.md) 使用这些契约实现任务推进。
