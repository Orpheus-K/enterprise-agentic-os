# 编写清晰代码

## 收紧实现

- 命名业务：使用领域术语；动词命名动作；避免含糊的 Manager、Helper、通用 utils 堆积。
- 拆分职责：函数完成一个动作；模块拥有一类状态；按职责拆分，不按任意行数拆碎。
- 显式依赖：构造注入；禁止隐藏全局可变状态、循环依赖和跨包内部导入。
- 验证边界：解析外部输入、模型输出与配置；内部使用可信类型，不逐层重复猜测和修补。
- 建模状态：使用明确枚举或联合类型；区分缺失、空值、失败与未知结果。
- 删除冗余：清理失效分支、重复实现、注释掉的代码；兼容逻辑必须绑定真实消费者与退出条件。
- 注释原因：记录约束与取舍；不翻译代码；不留下无责任归属的 TODO。

## 拒绝无据兜底

- 暴露错误：保留原因与操作上下文；在责任边界记录一次，向上返回可判断错误。
- 禁止掩盖：不 catch 后返回成功、空集合或默认业务值；不禁用检查来“修复”失败。
- 限制重试：只重试可恢复且副作用安全的失败；限定次数、截止时间和停止状态。
- 定义降级：仅实现已有产品契约中的降级；记录触发条件与可见结果，不串联猜测性备选路径。

## 统一语言

- 规范 Go：执行 gofmt；传递 context 与取消；显式处理 error；释放资源；禁止用 panic 表达正常业务错误。
- 规范 Python：标注公共接口类型；保持 Worker 无业务主状态；限制并发与临时文件；禁止可变默认参数和裸 except。
- 规范 TypeScript：开启 strict；用 unknown 校验外部数据；禁止以 any、非空断言或 ts-ignore 掩盖契约错误。
- 统一工具：复用仓库 formatter、lint、类型检查与锁文件；尚未配置时随实际脚手架建立，不编造现成命令。
- 复用开源：优先成熟上游；核对许可、维护、安全、体积与离线依赖；薄封装真实差异，不重造通用框架。

## 分层前端

- 固定栈：React＋TypeScript＋Vite；shadcn/ui＋Tailwind；禁止引入 Next.js/SSR。
- 组织组件：基础 UI → 通用组合 → 业务组件 → 页面；共享 UI 不访问业务 API。
- 管理状态：保留单一事实源；区分服务端数据与临时交互；不复制可推导状态，不用 effect 串联可直接表达的逻辑。
- 统一视觉：复用语义 Token；保持 Vercel 风格、亮暗主题、细边框与克制动效；禁止页面散落品牌色与重复样式。
- 保持可用：实现键盘、焦点、标签及必要的加载/空/错状态；禁用按钮不能替代后端授权。
- 维护上游：追踪 shadcn/ui 来源与改动；按真实复用封装，不为每个标签增加包装层。
