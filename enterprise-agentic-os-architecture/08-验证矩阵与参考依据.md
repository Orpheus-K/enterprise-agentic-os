# 08 验证矩阵与参考依据

## 一、总述：文档校验与产品验证分开

本篇定义未来实施必须完成的验证；当前只有文档整理交付，不存在已通过的架构实现、容量或安全测试。产品层 T01—T23 见 [需求验收文档](../enterprise-agentic-os-docs/07-验收标准与需求追踪.md)，这里用 V 编号补充实现机制的验证。

每份报告记录制品与依赖版本、环境、配置、数据规模、操作步骤、预期/实际结果、证据位置、责任人及残留风险。阈值尚未确定时不得以“测试能运行”代替性能达标。

## 二、架构验证矩阵

| 编号 | 验证内容 | 通过条件 | 关联产品场景 |
|---|---|---|---|
| V01 角色与制品 | 同一 Go 制品以单体和拆分角色运行，Worker 单独重启 | 业务规则与版本一致；计算重启不丢主状态；缺依赖明确禁用对应能力 | T05、T14 |
| V02 驱动契约 | SQLite 与 PG 分别执行原子提交、条件更新、任务认领、取消与恢复 | 对外业务语义一致；故障注入不出现状态/事件/outbox 半提交 | T06、T20 |
| V03 队列竞争 | 多节点领取、锁冲突、租约过期、旧节点迟到、延迟任务 | 无双重有效状态提交；未知外部效果可核对；重试有界且无永久饥饿 | T06、T07、T22 |
| V04 外部写入窗口 | 发出前崩溃、发出后响应丢失、落库前失败 | 可证明安全才重试；否则核对或人工收口；业务系统无重复效果 | T06、T22 |
| V05 审批恢复 | 长等待后重启、修改单价、旧卡片、伪造/重复令牌与撤权 | Token 不单独授权；批准绑定新版本；迟到回调不能推进终态 | T02—T08 |
| V06 RLS 与应用授权 | 使用池化连接交替租户；检查 owner/BYPASSRLS、函数和视图路径；SQLite 无 RLS 模式同测 | 无越权行、切片、标题或计数泄露；缺身份时失败关闭 | T08、T09、T19 |
| V07 ACL 同步与缓存 | 权限先到/内容先到、事件丢失、游标失效、缓存未清、撤权时交付 | 未获有效 ACL 不发布；当前授权不可确认则拒绝；失效可观测 | T08、T09 |
| V08 检索质量与安全 | 中文、多语种、稀疏授权集合、ANN 过滤与关系查询 | 检索结果出库前授权；召回与延迟达到预先确定目标；重排与模型不见无权文本 | T08、T10 |
| V09 Worker 与沙箱 | 超大/恶意文件、超时、取消、重复请求、越权网络/文件访问、迟到输出 | 资源受限、临时数据可清理、跨租户隔离；产物版本正确，取消不被迟到结果复活 | T12、T22 |
| V10 工具网关 | URL/参数注入、密钥泄露、令牌受众不匹配、工具停用、SOAP 错误与只读视图 | 不能任意代理请求；明文密钥不进入模型或日志；契约失配受控失败 | T12、T19、T21 |
| V11 IM 适配 | 长连接接管、重复消息、Webhook 验签、卡片降级、流式限流、群成员变化 | 同一业务动作仅有效一次；交互降级不绕审批；接收范围校验有效 | T07、T09、T14 |
| V12 模型适配 | 流式中断、工具参数不合法、预算用尽、端点故障及能力缺失 | 不越过数据边界回退；结果可验证；不支持能力明确报告 | T13、T21 |
| V13 观测与诊断 | 注入业务文本与密钥，生成支持包，隔离回放 | 默认无敏感原文；导出可预览；密钥剔除；回放无真实副作用，缺口明确 | T15、T19 |
| V14 版本与迁移 | V1 待审批、V2 新任务、事件格式变更、驱动迁移、应用回滚 | 老任务可解释；授权仍当前；不兼容阻断；新旧执行方不双写 | T16、T20 |
| V15 备份与灾备 | 联合恢复数据库、原件、密钥和审计，核对恢复点后外部动作 | 满足约定 RTO/RPO；文件与引用一致；不重放已成功副作用 | T06、T20 |
| V16 离线与资源 | 断开公网安装运行；最小核心在目标资源运行；完整解析另测 | 无隐藏下载/License 在线依赖；离线不用公网 IM；分别报告真实依赖和资源曲线 | T14、T20 |
| V17 集团候选 | 指定国产数据库、硬件、缓存、文件与沙箱组合运行全套契约 | 每组合有版本证据；不支持的事务/检索/虚拟化能力显式阻断 | T09、T13、T20 |
| V18 全链路与经营指标 | 报价正常、七五折修改审批、取消和其他套件样例 | 产物、来源、审批、交付、审计一致；绩效去重且人力估算有基线 | T01—T04、T10、T11、T18、T23 |
| V19 前端与 Monorepo | 静态构建并嵌入 Go；深层路由刷新；共享 UI 变更；主题与键盘交互 | 无 Next.js/SSR 或 Node 运行依赖；API 错误不被 SPA 回退掩盖；共享包依赖无环；亮暗主题、焦点和业务组件状态一致；开源依赖可追溯且离线资源齐全 | T14、T20，前端补充要求 |

历史回放、Skill 生成和人工纠错仍需执行产品 T15—T18；本矩阵不以基础设施验证替代这些业务测试。

## 三、阶段放行规则

M1 至少完成接入、身份、事务、模型边界和基础审计的相关项，并建立 V19 的前端构建与共享组件检查；M2 完成 V03—V05、V10 及版本恢复基础；M3 完成轻量交付、授权知识、隔离和备份相关项，并跑通报价全链路；M4 对实际交付组合完成 HA、容量、迁移和集团认证。

安全泄露、重复高风险副作用、审批绕过、不可解释的数据损坏均阻断相应上线。性能目标由实际负载与客户要求确定；未验证组合标为“规划/待认证”，不能借用另一环境报告。

## 四、事实核验与参考资料

以下为 2026-10-18 整理时使用的官方依据，旨在核实边界，不是锁定依赖版本。版本号、许可证和目标环境支持须在制品发布时再次核验。

| 官方资料 | 本文采用的有限结论 | 对应位置 |
|---|---|---|

| [pgvector](https://github.com/pgvector/pgvector) | 近似检索过滤影响召回，需按版本与查询策略验证 | 05、V08 |
| [ParadeDB pg_search 介绍](https://www.paradedb.com/blog/introducing-search) | pg_search 为全文搜索扩展方向，需单独验证交付条件 | 02、A05 |
| [shadcn/ui Vite 接入](https://ui.shadcn.com/docs/installation/vite) | React/Vite 路线可接入 shadcn/ui | 01、A02、V19 |

## 五、文档交付检查与收束

文档检查要求：九篇文件齐全、每篇总分总、相对链接有效；原始语言分工、五组 SPI、四项子系统、Day-2 支柱和三段研发顺序均有落点；所有 R01—R20 具备架构映射；基线/候选/待验证表述清楚；不以未经测量的百分比、绝对安全或完美复现作为承诺。

架构闭环为“需求→模块边界→驱动与状态语义→受控执行→交付运维→验证证据”。后续实施先按 [07 的里程碑](07-架构决策与研发路线.md) 推进，再以本篇和产品验收共同放行；全局入口返回 [README](README.md)。
