# 05 权限知识与计算隔离

## 一、总述：内容处理与权限更新独立，授权贯穿全部阶段

知识管道由内容解析流与权限同步流协作：内容变更触发解析、切片和向量更新，组织或协作者变化只更新 ACL 与授权版本。计算成本与权限新鲜度分开管理，不为了节省解析成本延后撤权。

本篇落实需求 R02、R10—R12、R14，并约束 Python Worker 和所有检索驱动。

## 二、双通道同步与发布一致性

| 流水线 | 输入 | 产物 | 一致性要求 |
|---|---|---|---|
| 内容流 | 获准文档、源版本、原件引用与摘要 | 解析结果、切片、Embedding、全文索引、引用锚点 | 每组索引关联同一内容版本；未完成版本不混入正式结果 |
| 权限流 | 员工、部门链、角色组、项目、文档协作者、继承与拒绝规则 | ACL 映射、授权版本、缓存失效通知 | 变更无需重新向量化；撤销优先于等待重建索引 |
| 删除流 | 源文件删除、访问撤回或保留期到期 | 不可检索标记、派生产物清理计划 | 先阻止访问，再按保留规则清理，不等待物理删除完成才撤权 |

不能假设源平台都有完整的增量事件。支持事件监听并配合周期核对；游标丢失、同步中断和全量恢复要可见。身份集合不只是“用户＋部门＋角色”并集，还要应用继承、显式拒绝、有效期与客户自定义规则，防止简单展开扩大权限。

内容先到而 ACL 未就绪时保持不可见；ACL 变化先到则立即影响授权，不等待新的内容版本。文档切片默认继承来源有效权限；若源存在更细粒度限制，须保留，不能仅靠文档级放行。

## 三、检索预过滤与最终输出校验

查询流程为：验证身份与租户→获得当前有效权限版本→生成数据库侧授权约束→并行向量/全文检索→融合重排→生成引用→交付前复核。任何未授权候选不得进入模型、Python 重排服务或用户可见的日志。

SQL WHERE/JOIN 的逻辑授权过滤与 ANN 索引物理扫描不是同一概念。pgvector 的近似索引可能在候选扫描后应用过滤，造成命中不足；需要针对实际版本评估迭代扫描、精确检索或分区等策略，不能仅凭一条 JOIN 就承诺高召回预过滤。[pgvector 官方说明](https://github.com/pgvector/pgvector)

授权必须在数据库查询返回应用之前落实；如驱动无法证明此边界，禁用该检索组合，不将未授权文本取回应用再过滤。安全测试与召回测试分开：零越权不代表召回合格，召回不足也不能以放松 ACL 补救。

权限缓存以租户、主体、策略版本和权限版本区分，设置失效与重新校验机制；通知仅加速失效，不替代权威版本检查。同步健康性或当前授权无法确认时回源验证或拒绝，不延用无时限缓存。

结构化查询经批准的语义指标层执行，保留行列权限；关系索引同样过滤节点、边和派生摘要。回答中区分原文事实、计算结果与推断。引用精确到可支持的位置，点击与预览重新鉴权；群聊接收范围不确定时使用受控链接而非敏感正文。

## 四、Python 能力面与不可信代码隔离

Python Worker 提供解析、Embedding、重排及算法服务。它可缓存模型和中间文件，但任务事实、批准和结果版本属于 Go 核心。每次请求限定对象、租户、资源和有效期，完成后回收临时数据；不能因为 Worker 无业务状态就忽略其中的数据和模型缓存隔离。

文档解析也面对恶意文件，应限制文件大小、解压膨胀、运行时间、资源和外部链接访问。模型下载、依赖获取在交付前完成，生产 Worker 不默认在线下载任意代码或模型。

受信解析服务与用户/模型生成代码是不同信任等级。生成 Python 在独立沙箱执行，不与拥有模型缓存、对象凭证或其他租户资料的解析进程共享不受限解释器。即便复用镜像构建材料，也应使用不同运行实例、身份和挂载权限。

| 沙箱路线 | 适用范围 | 限制与验证 |
|---|---|---|
| wazero/WASM | 已适配的受限计算模块、规则核算 | 显式控制 host functions、文件与网络；不假设任意 Python 包或原生 Office 依赖可运行 |
| 容器池/gVisor | 需要完整 Python 生态的文件与数据处理 | 只读基础镜像、最小权限、网络拒绝优先、资源上限与任务间清理；按工作负载认证 |
| Firecracker | 具备相应宿主能力的更强隔离工作负载 | 需要适配 Linux/KVM 等运行条件、镜像与网络管理；不是所有信创环境必然可用 |

wazero 提供 Go 中的 WebAssembly 运行能力，但具体程序兼容性仍需验证。[wazero 官方说明](https://wazero.io/) Firecracker 依赖基于 KVM 的微虚拟机路线，不能作为不考虑硬件条件的统一后端。[Firecracker 官方说明](https://firecracker-microvm.github.io/)

沙箱默认不允许任意访问宿主机、内部网段、元数据服务、其他任务目录或密钥。必须联网的业务通过获准工具或受限出口代理执行。超时中止、进程树回收、产物扫描与磁盘清理属于验收项，不把“用了某种沙箱”当成安全测试结果。

## 五、收束：隔离边界需要运维保持

权限、内容版本与计算环境共同决定是否可以安全产出结果。下一篇 [私有化部署与运维升级](06-私有化部署与运维升级.md) 将这些边界落实为部署配置、诊断导出、备份和升级过程。
