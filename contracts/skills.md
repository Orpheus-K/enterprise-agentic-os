# 加载固定版本技能

对齐 R08/R09、A03/A08、V05/V06；当前实现技能资产、授权与任务固定版本加载；自动意图路由和 MCP 调用尚未接入。

## 校验资产

- 组织：每包包含 `manifest.json` 与 `SKILL.md`；示例见 [合成报价](../examples/skills/synthetic-quotation/manifest.json)。声明 format=1、名称、发布者、摘要、触发条件、输入输出契约、异常规则、工具版本与示例。
- 固定：Revision = SHA-256(manifest 原始字节 + NUL + SKILL.md 原始字节)。任何字节改变都生成新版本；导入者须从受控部署清单提供期望摘要。样本 revision.sha256 仅便于核对，不是签名或可信来源证明。
- 拒绝：未知字段、尾随 JSON、摘要不符、重复版本、同名重复工具、无效标识、超限或空内容。manifest ≤32 KiB、指令 ≤64 KiB、工具 ≤32、示例 ≤16。
- 限定：当前输入输出契约是声明文本；尚未接入业务结构校验器。脚本字段不支持，不执行宿主代码，不拉取远程资源。发布者标签不代表可信认证。

## 渐进加载

1. 汇集：构造不可变 Registry；允许相同技能名的多个 Revision 共存，不自动替换旧版本。
2. 披露：Summaries 查询当前成员授权，只返回 Ref、摘要与触发条件，不暴露完整 SOP、示例和工具定义。
3. 选择：调用方传入明确 Ref；当前没有模糊意图路由，不把关键词猜测当授权或自动选用最新版。
4. 挂载：Load 重新授权精确技能版本，再逐个计算工具依赖与当前授权交集。返回独立切片，调用方修改不会污染其他任务。
5. 重验：此时授权只允许上下文加载；运行时已在模型和发送意图边界重新授权技能，实际工具调用仍须另行授权。工具结果不能通过此 Registry 自授权限。

## 授予最小权限

schema 7 新增 `iam.asset_grants`：tenant/member/app/kind/name/revision，kind 为 skill 或 tool。强制 RLS 约束当前租户与有效成员；运行账户只读，禁用实时生效。新版本不继承旧版本授权，技能许可不自动包含工具许可。

PostgreSQL AssetAuthorizer 复用身份模块 Within 事务；调用者须先由可信入口解析 Principal，不能从用户输入构造身份。当前身份映射与具体调用边界由后续运行时消费者持续重验。

## 验证与接续

- 单元证据：版本并存、摘要披露、撤权、工具交集、跨租户策略、错误传播、资产篡改、返回值隔离与仓库样本。
- 数据库证据：[资产授权测试](../services/core/internal/identity/postgres/assets_integration_test.go) 验证成员/租户/安装/版本隔离、禁止运行时自授、连接池清理及撤权。
- 下一步：完成报价贯穿样例；渐进路由与只读工具循环已接入。

## 绑定运行任务

- 配置：可选 skills 对象包含 selected（name/revision）及 assets（manifest_path/instructions_path/revision）数组；路径必须绝对路径，最多 64 包。由管理员固定期望摘要，启动时验证全部内容，缺失或篡改拒绝启动。
- 选择：selected 固定单技能；或以 routes 指定可路由的 name/revision 列表，二者互斥。最多 32 个候选，同名只能有一个候选版本，旧包可保留供在途任务恢复。
- 固定：schema 8 将 skill_name/skill_revision 写入任务，与任务和审计同事务。重放既有消息不改选新技能；无技能授权的新任务整体回滚。默认技能改变不改写旧任务，旧 Revision 文件须保留。
- 加载：Worker 按任务 Ref 重新授权并加载原版本，完整规则、契约与样例放入 system 消息；原用户文本单独放入 user 消息，不拼接成同一角色。
- 拦截：模型请求意图及发送意图取得任务锁后，按原任务成员重新查询精确技能授权；撤权不再调用模型/发送。移除技能配置或缺少原资产时，尚未生成响应的任务显式失败，不退回普通聊天。
- 限定：工具技能要求配置网关及支持单工具调用的模型；每任务最多执行四次工具，每轮重验当前授权。详见 [MCP 契约](mcp-gateway.md)。已保存响应的发送检查点复用原结果，并继续检查技能权限。
- 验证：[运行时测试](../services/core/internal/feishu/skill_integration_test.go) 验证 V1/V2 并存、关闭并重开数据库连接池、默认版本变更、消息幂等、角色分离、模型前和发送前撤权。仅合成数据和本机模型替身。

## 渐进路由与恢复

1. 入队：按当前成员授权与配置 routes 求交集，将候选 Ref 写入 schema 11 的 skill_routes，与任务和审计原子提交；无获准候选拒绝入队。相同消息不覆盖原候选。
2. 披露：Worker 按任务候选重新授权，仅把 Ref、摘要和触发条件交给模型；不包含完整 SOP、示例或工具。管理员改变 routes 只影响新任务。
3. 选择：沿用 model_running 外部意图和租约；模型只可返回一个候选的严格 name/revision JSON。null、额外字段、无权限或候选之外版本明确失败，不降级普通聊天。
4. 固定：模型返回后重验身份，取得任务锁后重验技能授权；保存选定 Ref、pending 和审计，同事务释放租约。下一步按已选 Ref 加载完整上下文；重启不再次路由。
5. 中断：选择未成功落库而模型意图已发出时，租约过期进入 unknown；不盲重试。已保存选择沿用原版本和既有技能/工具授权检查。

[真实数据库证据](../services/core/internal/feishu/routing_integration_test.go) 覆盖配置切换、消息重放、检查点恢复、选择篡改、撤权与审计故障。测试证明权限与恢复边界，不证明真实模型的意图识别准确率；实际模型需场景评测。

报价专用技能可声明 quotation_tool（tools 中的精确依赖名称），强制使用可信工具数据进行本地核价，禁止模型文本直接成为报价。声明参与技能 Revision；运行与业务权限要求见 [报价链路](quotation.md#接入-worker-核价链路)。
