# 04 权限安全与运营治理

## 一、总述：授权贯穿读取、执行与交付

数字员工的权限不得超出企业对当前主体和操作的授权。安全判断由可信规则与系统执行，模型、技能文本、文档内容和工具返回值均不能自行改变权限。轻量部署可以减少规模与运维能力，不能降低这一底线。

本篇承接 [03](03-产品能力与功能需求.md) 的 R02、R04、R06、R08、R10、R14、R15、R17、R20，定义它们共同遵循的规则。

## 二、从身份到知识访问

### 2.1 可信身份与最小授权

渠道用户标识须通过企业批准的映射关联员工、组织、项目和租户。单点登录解决登录体验，不能替代具体业务授权。映射不明确、身份源不可验证、账户停用或授权过期时停止敏感操作。

区分发起人、执行服务身份、审批人和接收人。服务账户具备底层连接权限不代表发起人有权使用全部数据。授权上下文全程可追溯，但不要求将同一用户原始 Token 传给所有系统；凭证须符合目标系统的受众、有效期与最小范围。

管理员配置平台的权力不自动等同于读取全部业务资料的权力。审批代理、跨部门授权和紧急操作必须来自企业明确规则，不能由 Agent 临时决定。

### 2.2 内容、切片与派生结果

同步内容时同时获取有效权限及继承关系，文档拆片后不得扩大可见范围。全文与向量检索都须先过滤再返回候选；重排、摘要、关系索引和缓存同样受权限约束。标题、命中数量、引用链接和错误提示不能成为侧信道。

权限变化必须传播到索引、缓存、派生摘要和待交付成果。同步周期及撤权生效时限由客户部署要求定义并测试；在无法确认有效授权时停止访问，不能以“上次允许”持续放行。外部源无法提供足够权限信息时，不得宣称已实现权限继承，应限制接入范围或使用经批准的独立授权。

执行中权限被撤销时，在下一次受保护读取、调用、审批和交付前重新判定。已经被接收者合法下载的文件无法靠平台撤权保证收回，需记录已发生交付并遵循企业处置流程。

### 2.3 群聊与引用交付

能读取不等于能公开到群。涉及客户、价格、毛利、合同或内部日志的输出，应检查接收范围；无法核实群成员权限时，仅返回不含敏感信息的状态，并使用私聊或权限保护链接。文件、审批卡片和引用预览均遵守同一规则。

引用应指向支持结论的真实位置，访问时再次鉴权。对没有直接原文的计算与推断，展示输入、口径、公式或推断标识，不能为了满足“每句有引用”而制造出处。

## 三、从工具授权到可信执行

| 环节 | 治理要求 | 报价场景表现 |
|---|---|---|
| 工具注册 | 说明业务负责人、读写风险、授权范围、结果核对与补偿能力 | CRM 读取与 ERP 写入分别登记 |
| 凭证与参数 | 凭证对模型不可见；校验参数范围；禁止从提示词或文档指定任意目标地址调用 | 客户编号与订单归属通过可信校验 |
| 风险判定 | 基于业务规则识别写入、发送、用章等高风险操作，不仅依赖模型分类 | 七五折触发特批，公章仍有独立授权 |
| 审批绑定 | 决策绑定任务、内容版本、规则和有权审批人；卡片回调校验来源与当前状态 | 单价修改产生新版本，旧批准不复用 |
| 故障恢复 | 已确认结果与待执行动作分开记录；结果未知时先核对 | ERP 超时不直接再建一次采购/报价单 |
| 补偿与取消 | 对可撤销操作使用明确补偿；不可撤销操作交责任人处理 | 已发送文件不声称能够完全撤回 |
| 限流与预算 | 按企业、工具或业务优先级限制调用；超限暂停、提示或转人工 | 不因模型循环无限查询客户记录 |

授权与审批在真正执行前仍须有效。审批不能解除源系统 ACL，也不能使越过审批人权限范围的动作合法化。卡片展示的内容与实际执行内容必须一致，避免批准后被替换。

## 四、数据、模型与运行隔离

文档、邮件、日志、网页和工具结果属于业务输入，不是系统指令。出现“忽略规则”“导出所有客户”等嵌入文本时，不能改变授权、工具范围、网络边界或审批要求；相关攻击样本进入上线前测试。

模型路由必须先满足数据位置、保密和外发规则，再考虑成本与能力。某个模型不可用时，不得自动改用不被允许的外部服务。模型服务、运行环境、文件处理和审计导出均遵守数据最小化。

脚本、Python 分析、图表和 Excel 处理在隔离环境内运行，限制计算资源、文件范围、执行时长和网络出口。默认不得任意访问宿主机、内部网段、其他任务文件或凭证；业务确需访问的数据通过明确授权的输入或工具提供。输出文件需通过类型和内容检查，不将恶意宏或外链作为可信交付。

## 五、可审计、可发布、可运营

### 5.1 审计与观测

记录任务关联标识、发起与执行主体、技能/规则/模型版本、来源引用、授权判断、工具调用状态、审批差异、交付对象及异常处理。保存恢复和审计需要的摘要与证据，不把记录模型内部思维链作为要求。

审计日志须可发现篡改、限制删除与导出权限，并按企业保留规则归档。日志脱敏不应抹去必要的责任证据；敏感内容与运行指标分级访问。审计系统失败时，应暂停不能满足审计要求的高风险动作并告警，不静默绕过。

平台提供任务级链路观测、失败定位、队列等待、审批积压、工具错误和资源成本视图；业务用户只见其有权任务。集团期支持统一监控接入和集中归档，具体观测协议留待技术设计。

### 5.2 发布与回放

技能、规则、模型和工具契约变化均评估影响。候选版本通过基本业务测试、权限负例、异常恢复和回放后才可发布。回放使用经过授权及必要脱敏的样本，真实写接口、发信、群消息推送、用章和外部业务变更被隔离，读取也须处于批准范围。

历史任务保留原版本关联，回滚影响后续任务；在途任务默认维持原技能版本，权限与安全规则仍按当前有效规则执行。严重安全问题可暂停受影响在途任务，经过核对再恢复，不静默切换造成业务解释失效。

## 六、收束：治理成为运营前提

治理的结果是每一次读取、写入、审批和交付都有明确授权与证据。下一篇 [数字员工与技能生命周期](05-数字员工与技能生命周期.md) 在这些约束下设计技能生产和持续改进，避免把“越用越聪明”变成未经审核的线上规则漂移。
