# 06 私有化部署与运维升级

## 一、总述：交付物必须包括运行与恢复能力

统一代码线解决版本来源问题，标准配置、兼容矩阵、备份与诊断流程解决现场维护问题。每个交付包记录制品摘要、依赖版本、启用驱动、技能版本、数据库迁移状态与目标平台，支持离线核验和可追溯升级。

“研发占 40%、交付运维占 60%”是重视 Day-2 的经验表达，本版不作为实测成本比例。维护目标通过安装耗时、升级失败率、恢复演练和故障定位时间验证。

## 二、部署形态与真实依赖

| 形态 | 运行组合 | 能力边界 |
|---|---|---|
| 最小核心 | Go all-in-one＋静态 UI＋SQLite＋本地文件 | 使用获准模型端点和兼容 WASM 能力；未安装 Worker 时不提供依赖 Python 的解析/计算 |
| 单机完整试点 | Go 核心＋Python Worker＋选定数据服务与文件存储 | 可单机部署多进程/容器，不宣称全栈单二进制或零依赖 |
| 生产 HA | 多个 Go 角色实例＋Worker 池＋PG HA＋共享文件存储 | 配置独立故障域、入口与连接所有权、数据库切换、备份和恢复；不以“多副本”替代端到端 HA |
| 集团/信创 | 已认证数据库、文件、沙箱与硬件组合，按需多区域 | 明确逻辑/物理隔离和数据驻留；多地域基线先验证主备灾备，多活另设冲突处理设计与门禁 |

2C4G 作为最小核心待测目标，不包含大型模型推理、重型解析与完整 HA。CPU 架构、操作系统、驱动原生依赖和扩展编译均列入发布矩阵，不能用“Go 静态编译”推导所有组合无需外部依赖。

PostgreSQL 是默认核心有状态服务；共享文件、外部模型和客户身份源是明确依赖。Redis、MinIO、消息总线仅按批准配置引入。HA 既包含服务多副本，也包含共享存储、数据库、凭证和外部依赖的故障处理。

## 三、离线交付与三镜像目标

基础制品目标保留三类镜像：Go 主控/网关、Python 能力 Worker、PostgreSQL 扩展镜像。三类镜像不等于三个运行实例，也不包括客户已有模型服务、模型权重、HA 管理组件、可选对象存储或微虚拟机运行环境。

原“Python 文档解析与沙箱合一镜像”只可理解为基础制品复用目标。解析与不可信代码必须在不同权限实例中执行；若隔离或依赖冲突要求拆分镜像，允许增加沙箱制品，优先满足安全和可维护性，不强行为三这个数量合并信任边界。

离线包包含镜像/二进制、校验与签名、软件物料清单、依赖和模型清单、许可证、安装与回滚说明、数据库迁移脚本和诊断工具。安装过程不得依赖在线拉取包、字体、模型、前端资源或许可证服务；离线授权的签发与续期规则由商业交付设计确定，授权异常不得阻止导出或恢复客户数据。

Air-Gapped 环境仅使用内网入口、内网身份与模型、获准数据源。公网飞书/钉钉连接在完全断网环境不可用；如客户使用专网可达的协同产品，作为单独适配验收。OpenAI 兼容模型入口逐项认证，不能用“兼容”替代工具调用、流式与模型质量测试。

## 四、可观测与脱敏支持包

OpenTelemetry 贯穿 IM 接入、身份展开、ACL、检索、模型、工具、Worker、审批恢复和交付。任务 ID 长期关联业务，Trace_ID 关联一次执行链路；长等待恢复可通过关联标识连接新的 trace，不要求一个 span 跨数小时持续打开。

默认记录时长、状态、错误分类、对象标识、版本、摘要和用量，不默认采集完整 Prompt、切片正文、工具入参出参或密钥。经客户授权的诊断模式可以限定任务、字段、访问人员与保留期采集额外内容，并保留开关审计。

支持包流程：选择有权任务→确定字段与范围→去除密钥及敏感配置→内容脱敏→生成清单与预览→客户确认导出→本地保存加密包与摘要。平台不自动将包发送给技术支持；传输目的地、审批与解密密钥管理由客户控制。

支持包可包含状态事件、版本化配置的脱敏副本、运行日志、组件版本和测试替身所需结构。回放在隔离环境使用录制结果或替身，不访问真实写接口。脱敏、未采集内容、模型随机性和外部状态变化会限制复现，报告须标注“可重放步骤”和“不可复现缺口”，不得承诺完美复现。

## 五、GitOps、升级和数据迁移

技能、提示模板、工具映射和策略引用以声明式资产版本化；密钥不进入 Git 或导出包。导入流程检查签名/来源、语法、依赖、权限和兼容性，产生候选版本，经过评测与批准再发布。企业可使用自己的 Git 流程，也可使用离线包，不强制生产环境能连接 Git 服务。

应用、技能、事件/快照、工具契约、数据库结构分别有版本。兼容升级采用先扩展后收缩的策略；删除旧字段、旧运行定义前确认没有依赖它们的在途任务和回滚需求。V1 审批任务可继续，但当前撤权与紧急安全封禁必须生效。

SQLite→PostgreSQL 或其他后端迁移采用：备份与演练→冻结高风险写入或安排单一执行方→迁移事实数据、文件与授权关系→重建索引→校验数量、摘要、任务与审批→切换入口→恢复运行。驱动替换不代表数据文件可直接互读。

回滚前判断数据库与事件是否仍向后兼容；不兼容则进入显式恢复流程。恢复旧备份后须核对备份时间之后已发生的外部写入，防止重发。数据库、原件、密钥与审计保留状态要联合演练，只有备份文件存在不算可恢复。
