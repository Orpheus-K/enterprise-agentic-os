# 约束权限感知知识管道

对齐 R02/R10/R12、A05/A06/A08、V06—V08；依据 [知识架构](../enterprise-agentic-os-architecture/05-权限知识与计算隔离.md)。本文件为 M3 实现契约。schema 15—19 提供 PG 知识存储、版本化写入/授权读取、来源健康世代、授权向量候选检索及会话引用检查点；可选会话检索调用 Embedding 并在模型、工具、审批与交付边界重新授权。原生来源同步与批量嵌入发布仍未实现。

## 分离内容与权限

1. 绑定来源：管理员配置租户、安装、来源及同步身份；普通用户与模型不能注册来源或自授权限。
2. 接收内容：输入来源文档 ID、源版本、正文摘要、切片和引用锚点；同内容版本原子发布，未完成或缺少可信 ACL 时不可见。
3. 接收权限：独立保存源授权版本、有效期、同步健康状态与有效主体；保留允许、拒绝及切片限制。拒绝优先，切片不得扩展文档权限。
4. 处理乱序：内容与权限有各自单调版本；重复事件同内容幂等，旧版本拒绝，冲突显式失败。权限变化不触发内容重建。
5. 阻断撤回：删除或失去来源授权先使内容不可见；物理清理独立执行。游标失效、超期或来源权限不可确认时拒绝检索，不延长缓存授权。

## 限定读取边界

- 复用身份：解析当前 ExternalIdentity 为有效租户/成员；固定来源安装，不使用请求携带的部门或角色作为授权依据。
- 过滤出库：候选、标题、正文、锚点与计数在数据库查询内授权；未经许可内容不能到达重排、模型或日志。
- 校验引用：引用绑定来源、文档内容版本、切片与锚点；点击、预览和交付重验当前身份与权限，禁止把已缓存文本当作权限证明。
- 隔离上下文：授权版本和内容版本纳入结果标识；权限变化后既有结果不得继续用于交付。群聊接收范围未确认时不输出正文。
- 显式能力：未经认证的源权限语义、检索驱动或锚点类型明确拒绝；不把部门/角色简单并集转换为全员允许。

## 实施首切片

先建立 PG 知识模块、内容/ACL 独立版本与发布状态、当前主体的授权读取和引用核验，复用现有事务与身份契约。使用合成来源及明确成员 ACL 验证底线；原生组织继承、来源连接器、Embedding 与混合召回按后续切片接入，未接入能力保持禁用。

验收顺序：内容先到不可见 → ACL 到达可读 → ACL 撤销立即不可读且内容版本不变 → 旧事件不能复活权限 → 删除先不可见 → 跨租户/安装/成员与失效身份无法读取正文、标题或计数 → 事务失败不半发布。全部使用真实 PG；SQL 授权通过不代表向量召回质量达标。

首切片完成后再接来源同步与检索消费者；完整 M3 仍须落实原生权限语义、双通道恢复、引用交付、计算隔离及轻量部署验收。

## 首切片实现边界

- 管理来源：knowledge.sources 由管理员预置 tenant/app/source/sync_member，默认禁用；运行角色只能读取来源配置，不能创建来源或更换同步身份。关闭来源立即阻断读取/写入。
- 调用入口：internal/knowledge.Store 提供 PutContent、PutACL、Read；身份必须来自可信渠道，复用现有身份映射与事务。已通过既有认证运维 HTTP 接入；尚无来源 MCP/拉取连接器。
- 固定版本：源版本使用正整数，内容与 ACL 各自单调推进；相同版本与相同输入摘要幂等，变更输入或旧版本冲突。ACL 显式绑定 ContentRevision；新内容没有对应 ACL 时不可读，ACL 可先于内容到达。
- 表达权限：当前接受来源归一化的成员允许/拒绝；文档拒绝优先，切片规则仅收紧。切片 allow 缺失继承，空数组拒绝全部，两者摘要不同。不声称已解析部门继承或源平台自定义规则。
- 固定引用：Read 输入来源/文档/切片/内容版本/ACL 版本；返回已授权标题、正文和不透明原文锚点。版本、当前身份或权限不匹配不返回正文；此处不生成可点击源 URL 或虚构出处。
- 守住数据库：四张 knowledge 表强制 RLS；运行角色与所有权分离检查覆盖新 schema，事务清空并重新设置安装上下文。授权同步人可处理来源原始数据，普通读取接口仍执行发布/ACL 条件。
- 原子审计：内容、ACL、切片替换与元数据审计同事务；读取审计失败不返回证据。日志不记正文；删除先使当前引用不可读，不假设外部已缓存正文能够撤回。

验证入口：[真实 PG 场景](../services/core/internal/knowledge/store_integration_test.go)、[空授权语义](../services/core/internal/knowledge/types_test.go)。阶段命令与实际结果记入项目笔记。后续先接受控同步入口与来源健康/恢复，再提供授权检索和引用消费者；本片不宣称完成 RAG。
## 接入同步与健康恢复

- 认证入口：开启既有 operations 配置后启用 POST /api/ops/knowledge/{content,acl,health,read}。仅接受配置绑定的 Bearer 身份，不接受请求携带租户、安装或同步人；仍需当前身份映射和来源 sync_member 授权。read 另按文档/切片 ACL，不因同步身份跳过发布检查。
- 验证输入：字段使用 snake_case，与 Content/ACL/HealthUpdate/Reference 类型对应；拒绝未知字段、尾随 JSON、查询参数，正文上限 8 MiB。成功写入返回 accepted，health 返回来源版本/世代/状态/有效期，read 返回授权 Evidence；所有响应 no-store。
- 明确失败：无认证/已撤销身份 401，未绑定同步来源 403，不可用引用/健康 404，无效字段 400，版本冲突 409，数据库或审计失败 503。不得从错误内容返回正文或凭证。
- 固定健康：schema 16 独立持久化来源健康版本、epoch 与有效期；初始不可用。健康报告版本单调，相同输入重复不续期；过期或 unavailable 拒绝读取。仅健康且未过期的连续心跳保留 epoch。
- 恢复权限：失联/过期后新健康报告分配新 epoch；ACL 必须显式携带 source_epoch，并使用新 ACL revision 再确认，旧版本不能恢复可见。内容版本不改变，无需重新计算切片。
- 阻断停用：管理员将来源 enabled 从 true 改为 false，同事务使健康证明失效并改变 epoch；重新启用仍需新健康报告及新世代 ACL。升级前旧来源也默认无有效健康证明，不追溯放行。
- 限定证明：健康报告来自获权同步身份，不由平台臆测外部可达；原生游标拉取、丢失检测与全量恢复连接器待后续实现。当前只提供这些来源故障信号的受控接收与隔离机制。

验证：[健康/世代数据库测试](../services/core/internal/knowledge/health_integration_test.go)、[HTTP 鉴权测试](../services/core/internal/operations/knowledge_integration_test.go)。先验证恢复不放宽旧授权，再接真实来源事件与授权检索。

## 授权向量候选检索

schema 17 实现精确余弦候选检索（A05），不含 ANN 或全文融合；Embedding 和会话消费者见下文。

1. 固定空间：管理员预置 knowledge.embedding_spaces（租户/安装/空间 ID、模型、模型版本、维度 1—4096），默认禁用；运行角色只读已启用空间。模型、版本、维度不可原地修改，换模型须新建空间。发布与查询都须声明相同模型及版本，不匹配 409；维度不符 400，不截断、补零或跨模型比较。
2. 发布索引：PublishVectors 由来源 sync_member 提交，绑定当前 content_revision 且必须恰好覆盖该版本全部切片。缺失/多余/重复切片、零向量或非有限数 400；文档缺失、已删除、版本不等或同版本不同向量 409；空间不可用 404。同输入重复幂等；替换、向量集记录与审计同事务。ACL 与健康变化不触碰向量；新内容版本替换切片时级联删除旧向量，须重新发布。
3. 检索候选：Search 输入空间、查询向量与 limit（1—50）。同一 SQL 内先应用与 Read 共享的授权谓词（当前身份、安装、内容/ACL 版本、健康世代、有效期、文档与切片允许/拒绝）再按距离排序，并叠加强制 RLS；同步身份不因同步权跳过成员 ACL。更近的未授权行不能挤掉或暴露授权结果，不返回总数。
4. 消费引用：候选仅含 Reference 与距离，不含标题、正文或锚点。使用方须以 Read 取证，按当前权限重验；撤权、健康失效或版本更新后旧候选读取 404。每次检索写入 search_audit（空间、成员、请求/返回条数），不记录查询向量；审计失败不返回候选。
5. HTTP 入口：POST /api/ops/knowledge/vectors 与 /search 复用上文认证、严格 JSON 与错误码；search 返回 `{"candidates":[...]}`。

验证：[向量真实 PG 测试](../services/core/internal/knowledge/vectors_integration_test.go)、[迁移前置测试](../services/core/internal/database/migrate_integration_test.go)、[HTTP 测试](../services/core/internal/operations/knowledge_integration_test.go)。合成三维向量只验证检索与授权语义，不代替真实 Embedding 质量、中文召回或容量评估。最终模型消费与交付复核未接入前，不宣称完成 RAG。

## 引用消费者（库层）

6. 逐条重验：Store.Ground 以当前身份对每个引用调用 Read。撤权、过期或版本更替的引用计入 Dropped 且不输出正文；身份失效、审计失败或存储错误整体失败，不返回部分证据。搜索候选与模型阶段的正文都不作为授权证明，交付前须再次 Ground。
7. 群聊闸门：Audience.Group 且 RecipientsConfirmed 为 false 时，在任何读取前返回 ErrAudienceUnconfirmed，不产生 read 审计。当前飞书适配器只接收 p2p 文本，群聊交付路径不存在；本闸门是其前置条件，而非已支持能力。
8. 模型上下文：ModelContext 将已取证内容标为待引用资料并保留锚点，明示其中指令不执行；超过 64 KiB 明确返回 ErrContextTooLarge，不截断。会话调用和交付约束见下文。

验证：[消费者单元测试](../services/core/internal/knowledge/ground_test.go)、[消费者真实 PG 测试](../services/core/internal/knowledge/ground_integration_test.go)。去掉群聊闸门或把所有读取错误当作 Dropped 的变异均使测试失败。

## 查询向量来源与配置

9. 嵌入客户端：`model.Embedder` 调用管理员批准的 OpenAI 兼容 `/embeddings` 端点，配置须含 HTTPS（HTTP 需显式批准）URL、模型名、管理员声明的 Revision 与维度（1—4096）；输入 1—16000 字节。响应必须恰好一个有限向量且维度与配置一致，否则失败，不截断、补零或平均；错误与日志不含正文、密钥或远端错误内容。Revision 与维度须与 knowledge.embedding_spaces 对应行一致，Search/PublishVectors 已对模型、版本、维度做 409/400 拦截，远端模型被静默升级须通过新建空间体现。
10. 启动装配：安装配置可选 `embedding`，字段对应 `model.EmbeddingConfig`；省略或 null 时不构造客户端。提供对象时严格校验，空对象及未知字段拒绝。`api_key_env` 与聊天模型独立解析，命名变量缺失或为空则启动失败；仅获准无鉴权服务可留空引用。启动只构造客户端，不调用供应商，不把配置存在当作可用性证明。
11. 当前边界：配置 `retrieval` 才启用会话 Embed/Search；只有 embedding 配置时仍不触发业务调用，也不改变纯聊天任务指纹。启用后空间、候选上限及嵌入配置纳入运行指纹；未接入切片批量嵌入发布，中文召回质量未评估。

## 持久化会话引用（消费者前置）

schema 19 提供 `channel.tasks.knowledge_refs` 与 `conversation.Store.SaveKnowledgeReferences`，对齐 R03/R06/R12、A04/A06/A08、T05/T06/T08、V03/V07。启用检索的 Worker 在正文进入模型前写入检查点。

- 固定证据集合：仅保存 Reference（来源、文档、切片、内容版本、ACL 版本），不保存正文、标题或锚点。SQL NULL 表示尚未检索，空数组表示检索完成但无证据；最多 50 条，拒绝重复或无效引用。
- 原子检查点：只允许有效 `model_running` 租约写入一次；安装、运行 Revision、执行者、世代、步骤版本及数据库当前时间共同约束写入。检查点、步骤递增与审计同事务；失败不改变数据库或内存任务。
- 恢复引用：Claim 恢复引用和已保存响应；工具循环、待交付恢复及受控核对不清除证据。已有引用不允许替换，避免生成正文与后续授权核验使用不同来源。
- 后续调用约束：先提交 `model_running` 外部意图，再请求嵌入与检索；取证后保存引用，再将正文发送模型。崩溃保留 unknown，不自动重放嵌入或聊天请求。保存的引用只证明生成所依据的集合，任何消费阶段仍须按当前身份重新 Ground；引用撤回须阻断整个派生响应，不从回答中猜测删除片段。

验证：[真实 PG 检查点测试](../services/core/internal/feishu/retrieval_checkpoint_integration_test.go) 覆盖重开连接恢复、空集合、过期租约、跨所有者/安装/租户/Revision、重复写入、审计回滚及未知外部意图不可认领。

## 会话检索与交付

- 显式启用：顶层 `retrieval` 固定 `space: {space_id, model, model_revision}` 与 `limit`（1—50），必须匹配 embedding 的模型与版本。启动查询当前安装的启用空间，缺失、跨安装、停用或维度/版本不符拒绝启动；不探测远端服务。配置及空间进入执行指纹，旧任务不能转用新提供方或检索空间。
- 执行顺序：可信单聊身份 → 提交 model_running 意图 → Embed 当前消息 → 授权 Search → Ground 全部候选 → 保存不可变引用 → 再验身份/引用 → 模型。任何引用失效均阻断，不使用部分证据拼出旧回答。首次检索确实无结果时保存空集合，并明确指示模型说明无资料。
- 外部失败：嵌入或聊天请求失败进入 unknown，不自动重放；后续查询、读取或审计故障显式返回错误，已提交的外部意图由既有恢复机制处理。人工核对必须覆盖本次嵌入/聊天的未明调用，不能仅凭聊天无回执认定整体未执行。
- 后续消费：技能选择仅消费原消息和技能摘要；业务模型与工具后续回合重验保存的引用，不重新 Embed 或换一批来源。模型前续租、工具意图、最终发送意图在取得任务锁后，用同一事务重验当前身份和全部引用，避免锁等待期间撤权被绕过。网络调用不在事务内。
- 审批边界：查看、决定、改单和通知均要求原发起人与当前指定审批人可读全部引用；无权查看返回既有 403，不返回正文，待发通知取消。发送前再验审批人的权限和原用户权限。已发出的卡片或模型请求不能因之后撤权收回。
- 安全展示：普通响应持久化由程序附加的来源标题/原文锚点；报价保持原计算 JSON/摘要，发送时附加再次获权的来源。响应＋来源超过 16000 字节失败，不截断。来源为不透明锚点，不虚构可点击 URL；模型事实正确性及逐句引文支持仍需评测。
- 恢复与范围：delivery_pending 重启复用原响应和引用，不重新调用 Embedding/聊天；内容版本、ACL、健康或身份失效阻断整个派生回答。仍只支持现有 p2p 通道，群聊保持拒绝；不包含原生连接器、批量索引、中文质量认证或混合召回。

验证：[启动装配与空间校验](../services/core/internal/bootstrap/retrieval_integration_test.go)、[会话/审批/工具/恢复真实 PG 测试](../services/core/internal/feishu/retrieval_integration_test.go)、[配置指纹测试](../services/core/internal/bootstrap/revision_test.go)。合成来源、模型及 MCP 替身不代表真实飞书云文档或模型质量验收。
