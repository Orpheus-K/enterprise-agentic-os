# 07 架构决策与研发路线

## 一、总述：区分架构基线、候选方案和上线证明

本篇记录设计决策，不将候选组件写成已有实现。架构基线用于指导研发；新增依赖、驱动或客户例外需记录原因、影响、迁移与退出条件，并通过 [08 验证矩阵](08-验证矩阵与参考依据.md)。

## 二、核心决策登记

| 编号 | 决策及状态 | 原因与约束 |
|---|---|---|
| A01 基线 | Go 模块化单体，按角色部署；Python 无状态能力 Worker | 避免两套业务实现；Worker 不拥有任务事务 |
| A02 基线 | React＋TypeScript＋Vite SPA，shadcn/ui＋Tailwind，静态产物嵌入 Go | 不采用 Next.js/SSR；Vercel 风格、设计 Token 与分层组件；优先复用成熟开源方案 |
| A03 基线 | PostgreSQL 为生产事实存储；SQLite 为轻量实现 | 先验证 PG 主路径，再做 SQLite 同契约适配；不得维护两套业务语义 |
| A04 基线 | 数据库事务队列＋租约＋outbox/inbox | 内存 Channel 只作唤醒；外部消息总线为扩展，不替代事实状态 |
| A05 基线 | pgvector；pg_search/BM25 为待认证全文目标 | 验证过滤召回、中文检索、许可、备份和扩展升级；不把候选写成已支持 |
| A06 基线 | 不可变运行版本＋事件/快照＋当前授权重验 | 兼顾恢复与版本追溯，拒绝过期权限继续执行 |
| A07 基线 | 工具凭证代办、显式授权、外部结果核对 | Token 不任意透传；不存在平台单方面保证的外部 exactly-once |
| A08 基线 | 内容/ACL 双通道，缓存不作为授权权威 | 无法确认权限时拒绝；任何检索实现都过安全负例 |
| A09 基线＋候选 | 统一沙箱契约；WASM、容器/gVisor、Firecracker 分负载认证 | 不把任意 Python 兼容性或宿主适配当作既定事实 |
| A10 基线 | 同一发布线、声明式资产、脱敏诊断、离线交付 | 三镜像为基础目标；安全要求允许增加独立制品 |
| A11 可选 | Redis、MinIO/NAS、企业消息总线、国产数据库 | 需明确业务/容量理由和认证范围，不在首期无限组合 |
| A12 基线 | Monorepo，前端 pnpm workspace，各语言保留独立工具链 | 应用、共享 UI、契约和服务边界清楚；统一 CI，禁止循环依赖；同一发布线构建 |

原始观点的澄清不会删除其目标：单二进制保留为最小核心体验；PG All-in-One 保留为减少中间件策略；免公网接入保留为在线内网体验；离线部署作为不同网络配置；低运维成本通过统一主线与标准交付验证。

## 三、研发里程碑与依赖

### M1 筑底：统一主链路与事实存储

搭建 Monorepo 与共享 UI 包、Go 模块边界、PG 事务与迁移、基础身份/租户模型、审计、飞书接入、模型网关和 React/Vite 控制台壳；建立 shadcn/ui＋Tailwind 主题、组件分层与基础检查。钉钉同步进行渠道能力核实，不作为首个闭环的重复实现要求。

产出是一条“消息→可信身份→持久化任务→获准模型→安全响应”的链路及契约测试。无 ACL 的生产资料、无授权的真实写接口不得接入。退出要求为接入去重、身份隔离、事务失败与基础可观测通过验证。

### M2 立魂：可恢复任务与受控工具

依赖 M1，落实事件状态机、租约、审批挂起/恢复、操作核对、渐进式技能、MCP 工具与凭证隔离。围绕报价初稿、七五折特批、主管修改和安全交付完成贯穿样例，使用受控数据与业务测试系统。

退出要求为重启恢复、重复回调、未知写结果、旧执行者迟到与技能版本并存测试通过。仍未覆盖的知识和计算能力不可用临时放权代替。

### M3 筑墙：知识授权与可交付试点

依赖 M2，完成内容/权限双通道、授权检索与引用、兼容 WASM 计算、Python 文档能力和必要隔离环境、审计查询与基础业务统计。实现 SQLite 轻量驱动、离线安装材料和备份恢复，并与 PG 运行同一业务契约测试。

退出要求为权限撤销、检索缓存隔离、群聊交付、代码隔离、迁移与安装测试通过，形成可交付首期。ROI 基础统计保留真实口径，完整看板与自动回放平台按产品增强期交付。

SQLite 分片范围（2026-10-20 用户确认）：首版只实现任务、审批、审计与身份。知识与向量在 SQLite 配置下明确拒绝启动；先抽取上述领域的窄存储接口，再以 PG/SQLite 同一行为契约覆盖事务、恢复、当前授权与跨租户拒绝。此为实现顺序与首版能力边界，不代表 M3 已退出或 SQLite 已实现，后续扩大范围须补实现与验证。

### M4 规模化与集团适配

在真实负载和业务证据上增加多节点 HA、Worker 池、发布回放、专家示范、完整绩效、多渠道与业务套件；再按客户要求认证国产数据库、硬件、集团隔离和跨地域灾备。跨地域多活单列设计，不因“可配置集群”而默认完成。

退出要求为目标组合的容量、故障切换、联合备份、回退及兼容测试全部有证据。排期与容量阈值由团队和客户目标制定，本篇不虚构日期与性能数字。

研发顺序不等于安全优先级：身份、最小授权、密钥保护、持久化和关键审计从 M1 即进入；M3 是完善治理覆盖，而不是首次引入安全。

## 四、与产品需求的映射

| 产品需求 | 架构责任 | 首次覆盖里程碑 |
|---|---|---|
| R01—R02 办公入口与身份 | 渠道 Adapter、UI Schema、Identity/Policy | M1，后续增加渠道 |
| R03—R06 执行与审批 | Runtime、事件、租约、操作账本、outbox | M2 |
| R07—R09 工具与技能 | Registry、MCP Gateway、Vault、声明式版本 | M2 |
| R10—R12 权限知识与引用 | 双通道同步、授权检索、语义指标与关系权限 | M3 基础，M4 混合分析 |
| R13—R14 模型与计算 | Model Gateway、gRPC Worker、Sandbox SPI | M1 模型边界，M3 完整隔离 |
| R15 审计观测 | 关键事件、OpenTelemetry、诊断包 | M1 基础，M3 完整交付 |
| R16—R18 示范、回放、绩效 | 技能候选生成、隔离回放、版本门禁与指标口径 | M2 基本门禁，M3 基础统计，M4 完整能力 |
| R19—R20 部署与集团 | 配置角色、认证驱动、备份迁移、隔离与配额 | M3 轻量交付，M4 生产/集团 |

对应产品阶段仍以 [产品分期](../enterprise-agentic-os-docs/06-产品分期与商业化规划.md) 为准，工程 M1/M2 是形成首期之前的内部里程碑，不应单独包装成已满足企业生产要求的产品版本。

## 五、需验证的选择与例外管理

| 验证项 | 责任角色 | 放行前产物 |
|---|---|---|
| Go 驱动、静态链接与目标 OS/架构 | 核心研发、交付 | 可重现构建和安装矩阵 |
| SQLite/LanceDB、PG 扩展与中文检索 | 存储、检索研发 | 同契约测试、质量与资源报告、依赖许可清单 |
| 飞书/钉钉/企微事件与卡片能力 | 集成研发 | 渠道应用类型和功能支持矩阵 |
| WASM/Python、容器、微虚拟机适配 | 安全、计算研发 | 工作负载能力矩阵与隔离测试 |
| 国产数据库及软硬件 | 数据、交付团队 | 明确版本的兼容和迁移报告 |
| 容量、RTO/RPO、2C4G 目标 | 运维、产品、客户 | 带场景与负载的 SLO 和恢复演练结果 |
| 模型兼容协议与能力 | 模型接入团队 | 版本、工具调用、结构化输出、流式与质量结果 |
| License、诊断保留与外发规则 | 产品、安全、交付 | 客户可审查的配置与离线流程 |

新增例外必须说明为什么现有主线不足、是否增加状态或权限边界、谁负责升级、如何回归和退出；未经认证不出现在支持清单中。

## 六、收束：路线通过验证闭环

研发按依赖推进，产品按业务价值验收。下一篇 [验证矩阵与参考依据](08-验证矩阵与参考依据.md) 将架构决策转为可重复的测试，使设计基线不变成未经验证的宣传结论。
