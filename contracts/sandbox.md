# 约束不可信计算沙箱

对齐 R13/R14、A09、V09；依据 [知识架构 §四](../enterprise-agentic-os-architecture/05-权限知识与计算隔离.md)。本文件为 M3 实现契约，按路线逐步认证，未列入“已实现”的路线不得宣称支持。

## 已实现：WASM 路线（wazero）

`internal/sandbox.Run` 在进程内运行经管理员批准的 WASM 模块：

1. 固定模块：Program 必须带管理员批准的 SHA-256；摘要缺失或不符、模块为空或超过 1 MiB 一律 ErrInvalid，不执行。
2. 零能力：不提供任何 host function，也不实例化 WASI，故无文件、网络、时钟、随机数、环境变量。模块声明的导入无法解析，实例化即失败。
3. 强制限额：Timeout（≤1 分钟）与 MemoryPages（≤256 页，即 16 MiB）为必填，零值拒绝而非默认放开。超时或调用方取消以 ErrTimeout 终止运行中的模块（含死循环），不返回部分结果；越界 memory.grow 在来宾内返回 -1，不占用宿主内存；声明内存超限的模块不能实例化。
4. 无残留：每次调用新建并关闭运行时，内存、全局变量和编译状态不跨任务保留。
5. 有界整数接口：参数和结果各最多 8 个，只接受 i32/i64；拒绝浮点、向量或引用签名。i32 输入须为零扩展的 32 位位模式（负数需由调用方显式编码），高位非零拒绝而非截断；i32 输出统一零扩展为 uint64。最多返回 64 字节整数，不接受内存指针作为自动读取协议。
6. 执行前检查：编译后、实例化前校验目标导出签名；不允许非法签名先执行模块启动段。合法模块启动段仍受超时和内存限额约束。
7. 显式失败：陷阱与运行时错误返回 ErrFailed；参数个数、导出名、类型或数量超限返回 ErrInvalid，错误不返回部分结果。

验证：[沙箱测试](../services/core/internal/sandbox/wasm_test.go) 使用手工组装的模块覆盖运算、篡改摘要、未知导出、宿主导入、内存上限与死循环。去掉摘要校验、内存上限或上下文中断的变异均使测试失败或超时。

## 固定折扣规则模块（WASM）

`quotation.ApprovalInSandbox` 在新沙箱中调用固定 SHA-256 的 [approval.wasm](../services/core/internal/quotation/rules/approval.wasm)，源文件为同目录 approval.wat。输入为标准总额、拟报总额（整数分）和 1—10000 基点阈值；金额须满足 1 ≤ 拟报总额 ≤ 标准总额 ≤ MaxMinor。宿主和模块各自校验，非法输入失败，不把错误当作无需审批。

模块用商和余数计算 `ceil(标准总额 × 基点 / 10000)`，比较拟报总额是否严格低于该值，避免大金额乘法溢出与浮点舍入。模块无导入、内存、启动函数、浮点数或可变状态；宿主设 1 秒超时、1 页内存上限，只接受一个 0/1 结果。它不读取目录、不授予审批或交付权限。

构建使用 WABT 1.0.34：`wat2wasm services/core/internal/quotation/rules/approval.wat -o services/core/internal/quotation/rules/approval.wasm`。摘要为 `b1899480373d1df63263bc8988fd36fe164fa9cec28c76c5dd436d53a9b49ec7`。二进制入库，正常 Go 构建不依赖 WABT；改变模块须重新构建、审查摘要并认证规则。差分测试用 Go big.Int 作为独立参照，覆盖阈值前后、最大金额、固定随机样本、非法输入及取消。

运行时通过 `quotation_wasm_sha256` 显式配置上述摘要；未知摘要启动拒绝，省略保持原 Go 路径。摘要纳入安装运行版本，开启/关闭/更换模块不接管旧版本任务或审批；原版本在途任务需由原批准配置处理。构造本身不运行模块。

启用后 SaveQuotation 在入库前运行折扣规则复核；AmendQuotation 在当前任务/审批锁和授权检查后，对新版本重新复核。目录验证、金额汇总、草稿摘要及独立大整数校验仍由可信 Go 执行，WASM 复核结果不符、取消、陷阱或超时均失败，不回退。改单仍创建新审批，即使价格提高到阈值之上也不能沿用旧审批。该路径只隔离折扣规则，不宣称整套报价或模型生成代码均已隔离。

验证：配置/摘要指纹测试、取消与不一致拒绝测试，及真实 PG＋MCP/模型替身的 wasm_normal、wasm_boundary、wasm_checkpoint_failure 贯通场景，覆盖七五折审批、八折边界、改单重审与工具结果恢复。

## 文本产物与扫描库

R14、A09：显式 `RunArtifact` 入口复用同一摘要、超时、内存和零宿主能力约束；原 `Run` 仍只返回整数。新 ABI 必须导出 `memory` 并返回两个 i32（偏移、字节数），实例化前检查。可信配置指定 `text/plain` 或 `application/json`、1—1048576 字节上限及必填扫描器；来宾不能指定文件路径、类型或扫描策略。不启用文件系统/WASI。

先校验长度与线性内存范围，再复制数据；拒绝非法 UTF-8、非文本控制字符、非法 JSON、脚本标记、PEM 头和 EICAR 标记。JSON 字符串及键解码后复查，防止 Unicode 转义绕过。随后调用现场扫描器，扫描器得到独立副本，不能篡改将要交付的字节。扫描失败或取消不返回部分结果。内置规则仅是保守内容检查，不宣称完整杀毒或任意秘密识别；现场扫描器负责获准的敏感内容/AV 策略，缺扫描器直接拒绝。

当前仅库层，未接入业务交付，HTML、PDF、压缩包和可执行文件类型均不支持。合成 WASM 测试覆盖真实内存提取、尺寸边界、越界指针、错误 ABI、文本/JSON、扫描拒绝/篡改、取消及转义负例；未进行真实文件杀毒认证。

## 指令计量评估（2026-10-21）

锁定依赖为 `github.com/tetratelabs/wazero v1.12.0`。核对该版本 [RuntimeConfig](https://github.com/wazero/wazero/blob/v1.12.0/config.go) 与 [FunctionListener](https://github.com/wazero/wazero/blob/v1.12.0/experimental/listener.go)：现有公开配置提供内存上限与上下文终止，没有可直接配置的指令 fuel 预算；listener 的粒度是函数调用，不是循环或指令。实测 `TestFunctionListenerDoesNotCountLoopInstructions` 中死循环只产生一次入口通知，最后由墙钟取消终止。

结论：本次不能利用锁定版本的上述 API 实现可靠指令计量；不提供或报告虚构指令数，也不把函数调用次数/墙钟时间换算成指令配额。字节码插桩或更换运行时需要额外验证所有控制流、启动段、间接调用、溢出和计量绕过，并重审模块摘要及升级路径，本次不引入。该结论限定于当前版本与接入方式，不宣称所有 WASM 运行时都不支持计量。
