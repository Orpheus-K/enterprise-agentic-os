# 企业级数字员工运行底座：架构文档集

## 一、总述：统一代码与业务语义，分阶段改变部署规模

架构基线 v0.1，整理日期 2026-10-18。本文档集承接 [产品需求文档](../enterprise-agentic-os-docs/README.md)，将“模块化单体＋统一存储抽象＋控制面与计算面解耦”转为工程边界、执行规则、部署策略和验证门禁。此次交付为架构设计，不表示组件已实现或兼容测试已通过。

采用 Go 核心、无状态 Python 能力 Worker、TypeScript＋React＋Vite 客户端控制台，组件基于 shadcn/ui，样式使用 Tailwind CSS，视觉遵循 Vercel 风格的简洁克制方向；不采用 Next.js 或服务端渲染。项目采用 Monorepo，按粒度封装组件并优先复用成熟开源能力。生产优先 PostgreSQL，轻量模式保留 SQLite 路径。默认减少基础设施，扩展通过同一发布线的进程角色和驱动实现，避免客户现场长期维护业务分支。

## 四、关键口径修正

- 单二进制指 Go 核心与静态 UI；完整文档解析、模型服务、数据库、Python 和高级沙箱可能需要额外组件。静态链接也需要按目标平台和驱动验证。
- PostgreSQL 是默认核心事务存储，不是所有数据仅存在一个进程。文件存储需要独立备份；Redis、对象存储和企业消息总线属于按条件启用的扩展。
- RLS、编译后二进制和沙箱均不是“绝对杜绝漏洞、逆向或逃逸”的保证；它们与权限、签名、测试和运维共同形成防线。
- 审批等待释放执行协程，不意味着数据库、存储、定时扫描与通知零资源消耗。外部操作无法仅凭本地事务保证端到端 exactly-once。
- 脱敏诊断包支持状态轨迹回放，不保证真实模型输出和第三方系统状态的完美复现。完全断网环境不能使用公网飞书、钉钉或外部模型。
- “2C4G”“研发 40%/运维 60%”“每多一个中间件成本翻倍”保留为资源目标或经验假设，未经测量不作产品承诺，也不沿用对 Python 或竞品的绝对性能与安全判断。

## 五、收束：先确定边界，再验证替换能力

本集选择统一主线，不追求任意后端任意组合。阅读 [01](01-总体架构与工程边界.md) 明确模块职责，依次推进到 [08](08-验证矩阵与参考依据.md) 的验证门禁；未通过门禁的候选只能作为规划，不能列为已支持能力。
