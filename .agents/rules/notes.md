# 记录里程碑

- 读取现状：继续迭代前读 [NOTES](../NOTES.md)，再核对代码、差异与证据；笔记不替代事实。
- 定义目标：写明当前里程碑、交付范围与完成条件；不把计划标成完成。
- 更新节点：仅在里程碑完成、关键判断变化、阻塞或交接时更新；不逐工具调用写流水账。
- 留存证据：记录改动位置、执行命令与结果；区分通过、失败和未运行。
- 记录判断：保留影响后续工作的取舍与原因；正式决策回写架构，笔记只留链接。
- 明确下一步：写可直接执行的动作、前提及未决问题；不自动启动下一里程碑。
- 压缩历史：维护一份当前快照；已关闭细节保留证据链接，替换过时状态，不复制需求与规范。
- 隔离并行：并行任务仅更新各自条目；合并前重读文件，避免覆盖其他工作。
- 保护数据：不记录密钥、客户正文或完整日志；引用脱敏证据。
- 控制篇幅：使用“动词＋关键词”；简单一次性修改无需另建笔记、日报或任务档案。
