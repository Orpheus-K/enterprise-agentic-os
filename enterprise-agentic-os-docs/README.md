# 企业级数字员工运行底座：产品需求文档集

## 一、总览：以可控业务闭环定义产品

本产品定位为 **Enterprise Agentic OS（企业级数字员工运行底座）**：让企业在既有办公入口中，将知识、业务工具、人工决策和可恢复的任务执行组织成可审计的数字员工。产品价值是业务完成质量、权限安全和持续维护能力，而不是流程画布节点数量。

本文档集为定位与需求规划基线 v0.1，面向产品、业务负责人、售前和研发。采用完整蓝图与分期落地相结合的方式，不指定编程语言、框架、数据库、消息队列、模型厂商或硬件。所有阶段均须保留权限、审批、受控写入和审计底线。

贯穿案例：销售在飞书中基于 A 公司会议纪要生成报价初稿；有效折扣低于八折时发起特批；主管修改后重新核算与校验；审批通过后生成对应版本的文件，按接收范围安全交付。

## 四、统一术语与规划约定

| 术语 | 本文含义 |
|---|---|
| 数字员工 | 有业务职责、可用技能、授权边界、负责人和绩效口径的运行主体 |
| Skill / 技能 | 可版本化的 SOP、关联工具、示例及校验规则集合；不能自行授予权限 |
| MCP | 工具接入协议；协议接入不等于业务授权、安全认证或执行成功 |
| Runtime / 执行面 | 承载任务状态、授权判断、工具执行、等待与恢复的能力集合 |
| 控制面 | 管理身份策略、技能版本、连接配置、发布规则和运营设置的能力集合 |
| ACL、RBAC、ABAC | 对象访问名单、基于角色与基于属性的权限机制；共同受企业授权源约束 |
| HITL | 高风险或不确定环节由人审核、补充信息或接管 |
| 持久化执行 | 保存必要状态，故障或长时间等待后可继续，并控制重复副作用 |
| 补偿 | 对已完成操作执行可审计的纠正动作；不保证所有业务动作均可撤销 |
| 渐进式披露 | 先展示技能摘要，命中后再加载必要指令、资料与工具 |
| 回放 | 用获准的历史样本评估候选版本；隔离真实写入和外部发送 |

原文中的“节省 80% 上下文”“小模型零成本”“90% 试用者卡在公网配置”“十分钟启动”“每句结论都有引用”“替代若干人力”等，属于假设或期望，不是既成事实或对外承诺。竞品能力须按实际版本、授权版本和部署条件比较，不使用“企业已全面抛弃”等未证实判断。详见 [07 的假设清单](07-验收标准与需求追踪.md#四风险假设与待决策事项)。

文档集按“价值→场景→能力→治理→运营→分期→验收”形成闭环。先用 [01](01-产品定位与价值主张.md) 确立产品边界，再让场景和验收共同约束实现；不能将尚未验证的商业判断或技术示例直接变成采购承诺。
