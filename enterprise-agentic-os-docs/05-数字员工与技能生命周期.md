# 05 数字员工与技能生命周期

## 一、总述：数字员工需要负责人和变更纪律

数字员工由职责、技能、工具权限、知识范围、审批规则和绩效口径共同定义。技能可不断改进，但每次上线都须有负责人、可追溯版本和验证证据。运营目标是稳定提升业务结果，而不是无监督地吸收所有历史操作。

本篇展开 R09、R16、R17、R18；安全与授权规则以 [04](04-权限安全与运营治理.md) 为准。

## 二、定义职责，再形成技能候选

### 2.1 数字员工档案

业务负责人定义服务对象、能完成的工作、不可执行的动作、人工接管联系人和成果标准。技能维护者负责 SOP 与样本，安全或系统负责人批准访问范围，业务发布负责人决定上线。高风险变更采用企业要求的复核与职责分离。

报价数字员工的职责是生成有依据的报价与按规则发起审批，不默认包含签合同、用章、向客户发送或修改正式订单。

### 2.2 技能包内容

| 内容 | 作用与要求 |
|---|---|
| 一句话摘要与适用条件 | 支持意图匹配，说明能解决的问题和不适用范围 |
| 可读 SOP 声明 | 使用 SKILL.md 或等价文档描述步骤、输入、输出、强制规则、异常及人工节点 |
| 关联工具与知识 | 列出所需能力、只读/写入边界和授权前提，不包含明文凭证 |
| 示例与反例 | 展示正确结果、缺失信息、拒绝和错误处理，不把示例当作完整规则 |
| 校验脚本与评测样本 | 校验金额、格式、规则与输出依据；脚本按 R14 隔离执行 |
| 版本与责任 | 记录维护者、依赖、审批记录、评测报告和适用范围 |

### 2.3 专家示范模式

专家在办公入口演示一次处理过程，或提供获准的优秀工单、排障记录和历史对话。系统先提取操作、判断依据、输入输出和人工修改，再识别未说明的规则、权限前提与异常缺口，最后生成待审技能包及样本。

单次示范不能证明全部业务边界。提炼结果中无法确定的规则标为待确认；专家补充正常与异常案例后，由维护者整理成正式候选。原始记录需要授权、脱敏和保留期控制，不能自动复制其中的客户资料、账号或密钥到共享技能。

## 三、候选到上线：逐步形成可信资产

技能状态为草稿、待审核、待评测、待发布、已发布、已停用或已归档；任何修改形成可比较版本。审核失败回到草稿，评测失败回到修改环节，不能绕过记录直接上线。

| 阶段 | 输入 | 处理与输出 | 下一步条件 |
|---|---|---|---|
| 规则审核 | 技能候选、来源及缺口 | 确认业务规则、权限、工具风险、异常分支与负责人 | 关键规则与授权前提明确 |
| 静态与场景检查 | 已审核候选 | 检查声明完整性、依赖可用性和代表性样例 | 正常、边界与失败路径可解释 |
| 红蓝对抗 | 权限与安全负例 | 尝试提示注入、跨租户读取、审批绕过、重复写入和数据外发 | 不存在未解决的关键安全失败 |
| 历史回放 | 获准历史样本和基线版本 | 隔离真实副作用，对比准确性、耗时、成本、人工介入及风险 | 达到场景发布门槛，差异由负责人确认 |
| 发布 | 候选版本及报告 | 指定使用范围、责任人和回退版本；先限定范围验证 | 运行观测可用，问题可暂停和回滚 |
| 运营 | 任务结果和用户反馈 | 持续发现业务质量、工具变化与异常 | 新问题进入下一版草稿，不直接改线上 |

“过去一个月 500 条提问”可作为回放样本设计示例，不能固定为所有客户标准。实际样本按使用授权、场景覆盖、风险和代表性确定，包含失败与拒绝案例，避免只回放成功任务。

## 四、运行时加载与版本纪律

数字员工初始仅暴露授权范围内的技能摘要；识别到报价意图后加载报价技能的完整规则及必要工具。多个技能匹配时依据任务范围选择，无法确定时请求澄清；不能为了提高命中率加载无关敏感资料。

任务固定技能版本和关联业务输入，按当前授权执行。工具或依赖发生不兼容变化时暂停并提示维护者，不静默替换为不等价流程。回滚和停用均保留历史任务证据；已停用技能不得创建新任务，在途任务按风险评估决定完成或暂停。

## 五、绩效与人工修改形成改进输入

### 5.1 看板展示业务成果

| 指标 | 计算或解释原则 |
|---|---|
| 有效处理量 | 按业务任务去重；标明完成、失败、取消、待审批和测试任务 |
| 违规命中 | 区分规则命中、最终确认违规和误报，不把所有触发审批算成违规 |
| 人工介入率 | 分开统计正常审批、补充信息、异常接管与结果修正 |
| 草稿修改率 | 以经过人工审阅且有可比版本的草稿为分母，区分业务条件变更与系统错误 |
| 周期与等待 | 区分模型/工具处理时长和人员审批等待；展示完整业务交付周期 |
| 工时与成本 | 使用客户确认的人工基线，扣除复核和纠错投入，计入实际资源与维护成本 |

“本月处理 1,240 单、拦截 15 单、修改率从 30% 降到 4%、节省 2.5 个人力”仅是看板示意文案，禁止显示为真实成果。展示真实数据时提供时间窗口、口径、样本量和可追溯任务。

### 5.2 差异反馈闭环

员工修改草稿时，在获准范围内比较前后版本，生成差异及候选原因：事实错误、格式偏好、业务条件变化、规则缺失或其他。只凭 Diff 不能断定原结果错误，需要业务复核。

候选样本经过授权检查、脱敏、去重和人工标注后，进入回归样本集或新技能版本。新版本仍走审核与评测流程；不得自动训练外部模型、扩大共享范围或直接改变价格与审批红线。

## 六、收束：技能迭代与业务价值同向

生命周期将专家经验转为可审查技能，再将实际运行的质量和修改证据转为下一版输入。下一篇 [产品分期与商业化规划](06-产品分期与商业化规划.md) 确定这些能力何时交付，以及如何用可验证套件支撑采购。
