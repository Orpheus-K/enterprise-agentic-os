# 约束权限感知知识管道

对齐 R02/R10/R12/R15/R18、A05/A06/A08/A10、V06—V08/V13；依据 [知识架构](../enterprise-agentic-os-architecture/05-权限知识与计算隔离.md)。本文件为 M3 实现契约。schema 15—22 提供 PG 知识存储、版本化写入/授权读取、来源健康、向量检索、会话引用及来源同步检查点；schema 25 增加独立授权的知识审计查询和基础统计。可选会话检索在模型、工具、审批与交付边界重新授权；原生来源与合成链路范围见 [飞书文档契约](feishu-docs.md)，真实租户联调尚未完成。

## 知识审计读取与统计

独立能力 `knowledge.audit.read` 按 tenant/member/app 由管理员授予，runtime 不能自行授予。任务 `audit.read`、知识内容权限、来源同步权或 `knowledge.reconcile` 都不隐含此能力。审计权限也不赋予内容读取或同步权限；历史元数据统计不依赖来源当前健康状态。SQLite 未实现知识库，不开放此能力或接口。

knowledge.audit 和 search_audit 将 INSERT 与 SELECT 分为独立 RLS 策略；原有“本人可写”策略不能因新增 SELECT 被扩展为“本人可读”。查询要求当前租户/安装、启用成员、当前外部身份映射和独立能力。库方法前后重验映射及授权；撤权、改绑或留痕失败不返回部分结果。每次成功分页/统计与 knowledge.audit_reads 留痕同事务；该表只向 runtime 授予 INSERT，不混入业务读取/检索计数。

POST `/api/ops/knowledge/stats` 使用现有运维 Bearer/配置身份，拒绝请求指定成员/租户。请求为 `[from,to)` 的 RFC3339 时间窗口，最长 92 天，必须对齐微秒：

```json
{"from":"2026-10-01T00:00:00Z","to":"2026-10-22T00:00:00Z"}
```

响应含同一查询快照下的 read_checks、searches、empty_searches、requested_candidates、returned_candidates。read_checks 仅计已提交的 `action=read`，包括引用验证和重复授权检查，并非用户点击、去重文档或业务任务数；searches 计已成功提交的 Search，包括返回零候选；失败/回滚请求不在该表中，不伪造失败率。requested_candidates 是各次请求上限之和，returned_candidates 是实际返回数量之和，两者不能推算召回率、ROI 或模型质量。没有 Prompt、正文、查询向量或成员明细。

POST `/api/ops/knowledge/audit` 在同一窗口增加 `kind`（events 或 searches）、`limit`（1—100）及可选 UUID `after`。按 recorded_at/id 稳定分页；未知、跨范围或跨安装游标返回空页，不探测他域事件。next_after 仅在有后续记录时提供。events 返回事件标识、时间、动作、来源/文档标识和版本；searches 返回事件标识、时间、空间标识和请求/返回数量；不返回成员标识或内容。示例：

```json
{"from":"2026-10-01T00:00:00Z","to":"2026-10-22T00:00:00Z","kind":"searches","limit":50}
```

两接口均为 no-store；缺认证 401、缺独立能力 403、非法窗口/字段 400、存储或留痕故障 503 且无结果。分页不是跨请求的冻结快照，之后提交的新事件可能在后续查询出现；统计两表通过同一 SQL 语句获得一致快照。数据库测试使用合成内容和真实 PG，不能替代真实租户运营口径验收。

## 分离内容与权限

1. 绑定来源：管理员配置租户、安装、来源及同步身份；普通用户与模型不能注册来源或自授权限。
2. 接收内容：输入来源文档 ID、源版本、正文摘要、切片和引用锚点；同内容版本原子发布，未完成或缺少可信 ACL 时不可见。
3. 接收权限：独立保存源授权版本、有效期、同步健康状态与有效主体；保留允许、拒绝及切片限制。拒绝优先，切片不得扩展文档权限。
4. 处理乱序：内容与权限有各自单调版本；重复事件同内容幂等，旧版本拒绝，冲突显式失败。权限变化不触发内容重建。
5. 阻断撤回：删除或失去来源授权先使内容不可见；物理清理独立执行。游标失效、超期或来源权限不可确认时拒绝检索，不延长缓存授权。

### 原子发布已准备的快照

`Store.Publish(Publication)` 将同来源、同文档、同内容版本的 Content、单空间 VectorSet、ACL 及三类审计记录放在一个事务中提交。源读取、规范化、有效权限核对和嵌入计算必须在事务外先完成；此接口不推导原生权限、不生成同步版本或健康证明，也不承担同步任务调度。

复用独立 PutContent、PublishVectors、PutACL 的版本冲突、幂等、切片全集、同步身份和健康世代检查，提交前再次检查同步权限、来源可用及 ACL 未过期。任何失败回滚全部替换，保留原有内容/ACL/向量；相同输入重试不重复写入审计。成功替换后旧引用不可用。拒绝删除型 Content、来源/文档/版本混搭。独立权限更新与删除继续使用原有接口，不要求重新计算向量。

真实 PG 验证见 `publication_integration_test.go`：缺向量、ACL 冲突、过期、错误世代和末步审计失败均不能半发布；重复请求幂等，成功新版本替换三个通道。同步执行器、原生游标和撤权接线仍待实现。

### 持久同步任务与发布围栏

schema 20 的 knowledge.sync_jobs 按租户、安装、来源、文档保存目标请求版本、配置 SHA-256、状态、租约 Token/截止时间及世代。表强制 RLS，仅当前来源同步身份可读写；不存凭证或正文。ScheduleSync 的请求版本为调度侧单调序号，与原生内容版本独立；同版本/同配置幂等，不同配置冲突，较新请求使旧租约失效，并原子记录调度审计。

ClaimSync 只领取指定来源和配置摘要的 pending 或租约过期任务，使用行锁与 SKIP LOCKED 避免双领。每次领取增加世代并生成新 Token，租期必须在 1 秒至 5 分钟之间。未领取到任务返回 ErrUnavailable；身份/数据库错误不能当作队列为空。过期接管重新准备快照，不复用旧进程中的数据。

PollSync 为轮询分配数据库内单调请求版本，不依赖主机时钟。相同配置的在途/未知任务不变，完成后才生成下一请求；新配置不得覆盖活跃租约或未知调用。配置升级须停止旧实例，不能用多个不同配置反复轮询同一来源。

PublishSync 在同一事务锁定匹配请求版本、配置、Token 和世代的任务，再执行原子发布与任务完成审计；发布末尾再次检查租约，过期则连同正文/ACL/向量回滚。提交结果未知时可用完全相同的租约及 Publication 重试：已完成且摘要相同仅确认成功，不重复发布/留痕；不同内容、旧世代或旧请求冲突。新请求不能被旧执行者确认完成。

原生用户凭证来源发布须使用 `PublishSyncForMembers`，提交同步者及每个 ACL allow 成员的外部身份/预期 IAM 成员证明；允许集合必须完整匹配，不能缺员、重复或跨租户。证明来自可信来源适配器，不能来自员工请求。该方法先取得任务锁及文档锁，再在同一事务重新解析全部身份，发布后、完成前再次复核；成员撤销或改绑使整笔回滚。逐个解析后恢复同步者事务上下文，避免审计或写入误用最后一个收件人的身份。它只验证 IAM 当前映射，不能替代原生文档权限检查或延长外部证明有效期。

存储 API 由[飞书来源同步器](feishu-docs.md)消费；未知结果核对见下文，尚无原生事件游标。当前不提供续租，超过租期必须拒绝发布。验证见 `sync_jobs_integration_test.go`：连接池重开、并发领取、过期接管、配置错配、读者 RLS、旧执行者拒绝、完成审计失败和提交前过期回滚。

### 同步 Embedding 意图与检查点

schema 21 在同一强制 RLS 任务行保存 embedding_pending、embedding_input、embedding_vectors。BeginSyncEmbedding 在网络调用前原子保存内容快照、固定 Space 和意图审计；重复调用拒绝，不把“已有意图”当作重放授权。一次意图覆盖整份文档的 Embedding 批次。

SaveSyncEmbedding 仅接受与意图的来源、文档、内容版本、空间及切片全集一致的完整 VectorSet，结果与审计原子保存后才清除 pending；相同结果保存幂等，不同结果冲突。输入及结果各限 16 MiB；不存 API Key。失败、崩溃或租约过期导致的未知批次保持 pending，ClaimSync 和较新 ScheduleSync 均不能接管/覆盖，不自动再次付费调用。过期执行者也不能补写结果；人工处理使用下述受控核对入口。

较新 ScheduleSync 在配置摘要不变时保留已保存的完整检查点，配置变化则清除已知结果。RefreshSyncEmbedding 只允许有效租约在原文发生变化时清除完整已知结果，不允许清除 pending 或无变化重算。清除与审计同事务，之后必须重新提交意图；不复用旧向量给新正文。

保存成功后进程退出，新的租约可通过 LoadSyncEmbedding 读取内容与向量检查点并留痕，不再次嵌入。检查点不保存 ACL：发布者必须重新检查当前来源权限/身份/健康，并构造当前 ACL。PublishSync 拒绝 pending，且已有检查点时要求发布内容与向量完全一致；不能用保存的向量配另一个正文。

这不保证批次内部分成功的成本恢复；部分结果不会伪装成完整结果，也不会自动重放。真实 PG 测试验证未知调用不接管/不覆盖、迟到结果拒绝、缺切片拒绝、检查点审计失败保留 pending、完整结果幂等、接管复用和篡改发布拒绝。

### 未知 Embedding 的受控核对

schema 22 新增不可变 sync_reconciliations 账本与独立 `knowledge.reconcile` 能力，不自动授予。`POST /api/ops/knowledge/sync/reconcile` 复用运维 Bearer 绑定身份，要求同时拥有来源同步权限和当前安装的 knowledge.reconcile；在任务行锁后重新解析 IAM、检查来源和能力，幂等重试也不能跳过撤权。

请求字段为 id（核对幂等 UUID）、source_id、document_id、request_revision、generation、config_hash、outcome、evidence_hash，以及可选 vectors。evidence_hash 为核对证据的 SHA-256；只记录摘要，不接受“超时所以没发生”的自动推断。操作者须独立保留可审查的供应商/网关证据。

- `not_sent`：确认整个批次未发出；禁止携带 vectors，清除意图，允许新租约重新准备并调用。
- `completed`：确认完整结果；必须携带与原意图匹配的完整 VectorSet，保存结果供新租约复用，不重新调用。

两种结论都只接受租约已过期、仍 pending 的目标请求/世代/配置。更新任务、增加世代使旧执行者失效、写不可变核对记录及审计在同一事务。相同 id 和请求摘要重试幂等；不同证据/内容复用 id 冲突。部分完成或结果仍不确定时不能选择上述结论，保持阻断。

HTTP 请求上限 8 MiB，拒绝未知字段、查询参数和尾随 JSON；成功 accepted，认证失败 401、能力不足 403、无效输入 400、状态冲突 409、数据库/审计故障 503，响应 no-store。真实 HTTP＋PG 测试覆盖两种恢复、活跃租约拒绝、缺权限/证据、错误世代、审计回滚、幂等、旧执行者及授权撤销。尚无核对 UI 或供应商结果自动查询。

## 同步任务查询

`POST /api/ops/knowledge/sync/inspect` 接收严格 JSON `{source_id, document_id}`，复用运维 Bearer、绑定身份及 no-store。每次要求当前来源同步权限和独立 `knowledge.reconcile` 授权；不按 Token 推导权限。返回 request_revision、generation、config_hash、持久 state、lease_active 和 embedding_state（none/pending/saved）。pending 只表示已记录意图：活跃租约可能仍在调用，过期也不证明未发送，必须通过带证据的 reconcile 处理。

存在输入时附 embedding 元数据：规范化输入的 SHA-256 hash、模型空间、内容版本和切片 ID；不返回正文、标题、向量、凭证或租约 Token。快照不锁定后续状态，不作为供应商执行结果证据；核对接口仍原子重验版本/世代/授权。查询无写入或外部调用。获权来源缺任务返回 404，无来源权限或缺能力 403，其余错误遵循运维接口；未知字段、查询参数及尾随 JSON 拒绝。此查询不等于来源健康或完整同步验收。

验证：运维 HTTP＋真实 PG 用例覆盖活跃/过期 pending、两种核对后的状态、缺能力、撤权、禁用来源、不可访问来源、缺任务与输出脱敏。

## 限定读取边界

- 复用身份：解析当前 ExternalIdentity 为有效租户/成员；固定来源安装，不使用请求携带的部门或角色作为授权依据。
- 过滤出库：候选、标题、正文、锚点与计数在数据库查询内授权；未经许可内容不能到达重排、模型或日志。
- 校验引用：引用绑定来源、文档内容版本、切片与锚点；点击、预览和交付重验当前身份与权限，禁止把已缓存文本当作权限证明。
- 隔离上下文：授权版本和内容版本纳入结果标识；权限变化后既有结果不得继续用于交付。群聊接收范围未确认时不输出正文。
- 显式能力：未经认证的源权限语义、检索驱动或锚点类型明确拒绝；不把部门/角色简单并集转换为全员允许。

## 实施首切片

先建立 PG 知识模块、内容/ACL 独立版本与发布状态、当前主体的授权读取和引用核验，复用现有事务与身份契约。使用合成来源及明确成员 ACL 验证底线；原生组织继承、来源连接器、Embedding 与混合召回按后续切片接入，未接入能力保持禁用。

验收顺序：内容先到不可见 → ACL 到达可读 → ACL 撤销立即不可读且内容版本不变 → 旧事件不能复活权限 → 删除先不可见 → 跨租户/安装/成员与失效身份无法读取正文、标题或计数 → 事务失败不半发布。全部使用真实 PG；SQL 授权通过不代表向量召回质量达标。

首切片完成后再接来源同步与检索消费者；完整 M3 仍须落实原生权限语义、双通道恢复、引用交付、计算隔离及轻量部署验收。

## 首切片实现边界

- 管理来源：knowledge.sources 由管理员预置 tenant/app/source/sync_member，默认禁用；运行角色只能读取来源配置，不能创建来源或更换同步身份。关闭来源立即阻断读取/写入。
- 调用入口：internal/knowledge.Store 提供 PutContent、PutACL、Read；身份必须来自可信渠道，复用现有身份映射与事务。已通过既有认证运维 HTTP 接入；飞书拉取连接器见[来源契约](feishu-docs.md)，尚无来源 MCP。
- 固定版本：源版本使用正整数，内容与 ACL 各自单调推进；相同版本与相同输入摘要幂等，变更输入或旧版本冲突。ACL 显式绑定 ContentRevision；新内容没有对应 ACL 时不可读，ACL 可先于内容到达。
- 表达权限：当前接受来源归一化的成员允许/拒绝；文档拒绝优先，切片规则仅收紧。切片 allow 缺失继承，空数组拒绝全部，两者摘要不同。不声称已解析部门继承或源平台自定义规则。
- 固定引用：Read 输入来源/文档/切片/内容版本/ACL 版本；返回已授权标题、正文和不透明原文锚点。版本、当前身份或权限不匹配不返回正文；此处不生成可点击源 URL 或虚构出处。
- 守住数据库：四张 knowledge 表强制 RLS；运行角色与所有权分离检查覆盖新 schema，事务清空并重新设置安装上下文。授权同步人可处理来源原始数据，普通读取接口仍执行发布/ACL 条件。
- 原子审计：内容、ACL、切片替换与元数据审计同事务；读取审计失败不返回证据。日志不记正文；删除先使当前引用不可读，不假设外部已缓存正文能够撤回。

验证入口：[真实 PG 场景](../services/core/internal/knowledge/store_integration_test.go)、[空授权语义](../services/core/internal/knowledge/types_test.go)。阶段命令与实际结果记入项目笔记。后续先接受控同步入口与来源健康/恢复，再提供授权检索和引用消费者；本片不宣称完成 RAG。
## 接入同步与健康恢复

- 认证入口：开启既有 operations 配置后启用 POST /api/ops/knowledge/{content,acl,health,read}。仅接受配置绑定的 Bearer 身份，不接受请求携带租户、安装或同步人；仍需当前身份映射和来源 sync_member 授权。read 另按文档/切片 ACL，不因同步身份跳过发布检查。
- 验证输入：字段使用 snake_case，与 Content/ACL/HealthUpdate/Reference 类型对应；拒绝未知字段、尾随 JSON、查询参数，正文上限 8 MiB。成功写入返回 accepted，health 返回来源版本/世代/状态/有效期，read 返回授权 Evidence；所有响应 no-store。
- 明确失败：无认证/已撤销身份 401，未绑定同步来源 403，不可用引用/健康 404，无效字段 400，版本冲突 409，数据库或审计失败 503。不得从错误内容返回正文或凭证。
- 固定健康：schema 16 独立持久化来源健康版本、epoch 与有效期；初始不可用。健康报告版本单调，相同输入重复不续期；过期或 unavailable 拒绝读取。仅健康且未过期的连续心跳保留 epoch。
- 恢复权限：失联/过期后新健康报告分配新 epoch；ACL 必须显式携带 source_epoch，并使用新 ACL revision 再确认，旧版本不能恢复可见。内容版本不改变，无需重新计算切片。
- 阻断停用：管理员将来源 enabled 从 true 改为 false，同事务使健康证明失效并改变 epoch；重新启用仍需新健康报告及新世代 ACL。升级前旧来源也默认无有效健康证明，不追溯放行。
- 限定证明：健康报告来自获权同步身份，不由平台臆测外部可达；原生游标拉取、丢失检测与全量恢复连接器待后续实现。当前只提供这些来源故障信号的受控接收与隔离机制。

验证：[健康/世代数据库测试](../services/core/internal/knowledge/health_integration_test.go)、[HTTP 鉴权测试](../services/core/internal/operations/knowledge_integration_test.go)。先验证恢复不放宽旧授权，再接真实来源事件与授权检索。

## 授权向量候选检索

schema 17 实现精确余弦候选检索（A05），不含 ANN 或全文融合；Embedding 和会话消费者见下文。

1. 固定空间：管理员预置 knowledge.embedding_spaces（租户/安装/空间 ID、模型、模型版本、维度 1—4096），默认禁用；运行角色只读已启用空间。模型、版本、维度不可原地修改，换模型须新建空间。发布与查询都须声明相同模型及版本，不匹配 409；维度不符 400，不截断、补零或跨模型比较。
2. 发布索引：PublishVectors 由来源 sync_member 提交，绑定当前 content_revision 且必须恰好覆盖该版本全部切片。缺失/多余/重复切片、零向量或非有限数 400；文档缺失、已删除、版本不等或同版本不同向量 409；空间不可用 404。同输入重复幂等；替换、向量集记录与审计同事务。ACL 与健康变化不触碰向量；新内容版本替换切片时级联删除旧向量，须重新发布。
3. 检索候选：Search 输入空间、查询向量与 limit（1—50）。同一 SQL 内先应用与 Read 共享的授权谓词（当前身份、安装、内容/ACL 版本、健康世代、有效期、文档与切片允许/拒绝）再按距离排序，并叠加强制 RLS；同步身份不因同步权跳过成员 ACL。更近的未授权行不能挤掉或暴露授权结果，不返回总数。
4. 消费引用：候选仅含 Reference 与距离，不含标题、正文或锚点。使用方须以 Read 取证，按当前权限重验；撤权、健康失效或版本更新后旧候选读取 404。每次检索写入 search_audit（空间、成员、请求/返回条数），不记录查询向量；审计失败不返回候选。
5. HTTP 入口：POST /api/ops/knowledge/vectors 与 /search 复用上文认证、严格 JSON 与错误码；search 返回 `{"candidates":[...]}`。

验证：[向量真实 PG 测试](../services/core/internal/knowledge/vectors_integration_test.go)、[迁移前置测试](../services/core/internal/database/migrate_integration_test.go)、[HTTP 测试](../services/core/internal/operations/knowledge_integration_test.go)。合成三维向量只验证检索与授权语义，不代替真实 Embedding 质量、中文召回或容量评估。最终模型消费与交付复核未接入前，不宣称完成 RAG。

## 引用消费者（库层）

6. 逐条重验：Store.Ground 以当前身份对每个引用调用 Read。撤权、过期或版本更替的引用计入 Dropped 且不输出正文；身份失效、审计失败或存储错误整体失败，不返回部分证据。搜索候选与模型阶段的正文都不作为授权证明，交付前须再次 Ground。
7. 群聊闸门：Audience.Group 为 true 时，在任何读取前返回 ErrAudienceUnconfirmed，不产生 read 审计；移除可由调用方自行声明的 RecipientsConfirmed。群聊证明库见下节，尚未接入渠道。当前飞书适配器只接收 p2p 文本，群聊交付路径不存在。
8. 模型上下文：ModelContext 将已取证内容标为待引用资料并保留锚点，明示其中指令不执行；超过 64 KiB 明确返回 ErrContextTooLarge，不截断。会话调用和交付约束见下文。

验证：[消费者单元测试](../services/core/internal/knowledge/ground_test.go)、[消费者真实 PG 测试](../services/core/internal/knowledge/ground_integration_test.go)。去掉群聊闸门或把所有读取错误当作 Dropped 的变异均使测试失败。

### 群聊接收范围证明库

R01/R12、A08、V07：`VerifyGroupAudience` 要求可信 `AudienceAuthority` 提供租户/应用/群绑定的完整成员快照、版本和有效期；调用方期望接收者与权威集合必须完全相等（顺序无关），空集合、重复成员、跨租户、分页未完、过期或错群/应用均拒绝。逐人复核当前身份和全部引用权限，错误及审计失败不产生证明；随后重新读取完整范围，版本或成员改变即失败。输入绑定不可变内容摘要和运行版本，返回值仅为本次检查凭据。

该库不获取真实群成员、不发送消息、不自动授权，也不将多个外部检查声明为原子操作。未来渠道必须在交付点重验，并明确从证明到外发之间的成员变更控制；当前没有已认证实现，因此单人 Ground 和渠道继续拒绝群聊。合成测试覆盖集合相等/乱序、漏人/增员、重复、跨租户、缺完整性、失效、撤权、检查中换版/到期、供应商失败、取消和摘要/引用错误，不作为真实群聊验收。

前置环境：[向量驱动部署与探针](../deploy/postgres/README.md#准备向量驱动)。驱动探针与业务验收分别记录。
## 查询向量来源与配置

9. 嵌入客户端：`model.Embedder` 调用管理员批准的 OpenAI 兼容 `/embeddings` 端点，配置须含 HTTPS（HTTP 需显式批准）URL、模型名、管理员声明的 Revision 与维度（1—4096）；输入 1—16000 字节。响应必须恰好一个有限向量且维度与配置一致，否则失败，不截断、补零或平均；错误与日志不含正文、密钥或远端错误内容。Revision 与维度须与 knowledge.embedding_spaces 对应行一致，Search/PublishVectors 已对模型、版本、维度做 409/400 拦截，远端模型被静默升级须通过新建空间体现。
10. 启动装配：安装配置可选 `embedding`，字段对应 `model.EmbeddingConfig`；省略或 null 时不构造客户端。提供对象时严格校验，空对象及未知字段拒绝。`api_key_env` 与聊天模型独立解析，命名变量缺失或为空则启动失败；仅获准无鉴权服务可留空引用。启动只构造客户端，不调用供应商，不把配置存在当作可用性证明。
11. 当前边界：配置 `retrieval` 才启用会话 Embed/Search；只有 embedding 配置时仍不触发业务调用，也不改变纯聊天任务指纹。启用后空间、候选上限及嵌入配置纳入运行指纹；来源批量嵌入发布由 sources 配置独立启用，中文召回质量未评估。

## 持久化会话引用（消费者前置）

schema 19 提供 `channel.tasks.knowledge_refs` 与 `conversation.Store.SaveKnowledgeReferences`，对齐 R03/R06/R12、A04/A06/A08、T05/T06/T08、V03/V07。启用检索的 Worker 在正文进入模型前写入检查点。

- 固定证据集合：仅保存 Reference（来源、文档、切片、内容版本、ACL 版本），不保存正文、标题或锚点。SQL NULL 表示尚未检索，空数组表示检索完成但无证据；最多 50 条，拒绝重复或无效引用。
- 原子检查点：只允许有效 `model_running` 租约写入一次；安装、运行 Revision、执行者、世代、步骤版本及数据库当前时间共同约束写入。检查点、步骤递增与审计同事务；失败不改变数据库或内存任务。
- 恢复引用：Claim 恢复引用和已保存响应；工具循环、待交付恢复及受控核对不清除证据。已有引用不允许替换，避免生成正文与后续授权核验使用不同来源。
- 后续调用约束：先提交 `model_running` 外部意图，再请求嵌入与检索；取证后保存引用，再将正文发送模型。崩溃保留 unknown，不自动重放嵌入或聊天请求。保存的引用只证明生成所依据的集合，任何消费阶段仍须按当前身份重新 Ground；引用撤回须阻断整个派生响应，不从回答中猜测删除片段。

验证：[真实 PG 检查点测试](../services/core/internal/feishu/retrieval_checkpoint_integration_test.go) 覆盖重开连接恢复、空集合、过期租约、跨所有者/安装/租户/Revision、重复写入、审计回滚及未知外部意图不可认领。

## 会话检索与交付

- 显式启用：顶层 `retrieval` 固定 `space: {space_id, model, model_revision}` 与 `limit`（1—50），必须匹配 embedding 的模型与版本。启动查询当前安装的启用空间，缺失、跨安装、停用或维度/版本不符拒绝启动；不探测远端服务。配置及空间进入执行指纹，旧任务不能转用新提供方或检索空间。
- 执行顺序：可信单聊身份 → 提交 model_running 意图 → Embed 当前消息 → 授权 Search → Ground 全部候选 → 保存不可变引用 → 再验身份/引用 → 模型。任何引用失效均阻断，不使用部分证据拼出旧回答。首次检索确实无结果时保存空集合，并明确指示模型说明无资料。
- 外部失败：嵌入或聊天请求失败进入 unknown，不自动重放；后续查询、读取或审计故障显式返回错误，已提交的外部意图由既有恢复机制处理。人工核对必须覆盖本次嵌入/聊天的未明调用，不能仅凭聊天无回执认定整体未执行。
- 后续消费：技能选择仅消费原消息和技能摘要；业务模型与工具后续回合重验保存的引用，不重新 Embed 或换一批来源。模型前续租、工具意图、最终发送意图在取得任务锁后，用同一事务重验当前身份和全部引用，避免锁等待期间撤权被绕过。网络调用不在事务内。
- 审批边界：查看、决定、改单和通知均要求原发起人与当前指定审批人可读全部引用；无权查看返回既有 403，不返回正文，待发通知取消。发送前再验审批人的权限和原用户权限。已发出的卡片或模型请求不能因之后撤权收回。
- 安全展示：普通响应持久化由程序附加的来源标题/原文锚点；报价保持原计算 JSON/摘要，发送时附加再次获权的来源。响应＋来源超过 16000 字节失败，不截断。来源为不透明锚点，不虚构可点击 URL；模型事实正确性及逐句引文支持仍需评测。
- 恢复与范围：delivery_pending 重启复用原响应和引用，不重新调用 Embedding/聊天；内容版本、ACL、健康或身份失效阻断整个派生回答。仍只支持现有 p2p 通道，群聊保持拒绝；不包含原生连接器、批量索引、中文质量认证或混合召回。
